第三章 标注体系与配比设计

3.1 体系怎么建

不沿用本地八类与 S/I/X 分面，按 Arena 的方法重建，并以公开 benchmark 的划分做对照：

  1. 收集真实 prompt：采购会话的真人首轮请求 + 公开任务集（VIBE、WebGen-Instruct 6,667 条、MiniAppBench 真实 seed）作为外部参照。
  2. 聚类：LLM 先把每条 prompt 摘要为"用户意图 + 任务结构"，再 embedding 聚类。
  3. 迭代修订：以 Arena 七类为初始骨架，人工合并 / 拆分簇，优化四个目标：可解释、覆盖、统计稳健、边界清晰；一条 prompt 允许多标签 Arena §15.5。
  4. 命名约束：自建结果只能称"重建 taxonomy"，不得冒称某团队的官方类目（如 MiMo 的八类至今不可考）调研 §14.3.5。
  5. 标注与复核：低价模型在固定取值表内打标，温度 0；先抽 300 条人工复核，一致率 ≥ 85% 再全量，否则修订取值定义 本方案。
  6. 漂移：每季度对新数据重新聚类，同时看比例与绝对量 Arena §15.7。

3.2 正交标注轴

原则：用户意图、任务形态、技术实现、验证方式是不同维度，不能互相替代或混成一级类别；例如 React / HTML 是栈，不能当作第八个意图 Arena §15.6。
