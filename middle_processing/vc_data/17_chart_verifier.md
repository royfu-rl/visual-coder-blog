# 17 图表 / SVG / 示意图：逐值可验的 verifier

调研与实测日期 2026-10-15。代码 `scripts/vc_verifier/chart/`，阈值 `chart/THRESHOLDS.md`（跑之前写死）。
方法论沿用 `90_local_experiments.md`：分层判据、准入测试、变异测试、留出验证、verifier 信息量不得超过题面。
感知指标本身的性质见 `04_verifier.md`，本文不重复，只给图表任务上的实测判别力。

## 0 结论先行

1. **这类任务和别的 visual coding 不一样的地方，是判定可以不带容差。**
   输入数据已知，所以「画出来的东西」能被还原成数值再逐个比对。
   本机实测：同一页面重复渲染 5 次，几何回读**逐位完全相同**，截图 md5 也只有 1 种。
   这不是「噪声很小」，是这一环确实为零。噪声只可能来自题面的歧义，不来自 verifier。
2. **回读必须从「画出来的几何」走，不能从「配置对象」走。**
   读 `datasets[].data` 只是把模型写进去的那份数字读回来，模型画错了一样读到对的值。
   读柱子的像素坐标再用坐标轴刻度反推，才是读「屏幕上真实存在的那根柱子有多高」。
3. **逐值回读和结构断言是互补的，不是替代。**
   16 个变异上：逐值回读 13/16、结构断言 14/16、两者取或 **16/16**；像素比对只有 9/16。
   逐值回读漏掉的三个（轴截断、图表类型错、轴标题丢）全部不是数据错；
   结构断言漏掉的两个全部是纯数据错。两边的盲区精确互补。
4. **像素比对在这件事上是净负担。** 16 个变异里它判错 7 个，其中 5 个是把换配色、换字体、
   挪图例、改柱宽这类纯外观改动误杀。这与学界四组独立实测同向（见第 3 节）。
5. **这件事已经有人做过，不用自己发明口径。** ChartMimic 的 code tracer、Chart2Code 的
   matplotlib artist introspection、Chart Specification 的运行时拦截、D3 Deconstructor 的
   DOM `__data__`，都是同一条路。可以直接对齐，不必从零设计。
6. **位图回读和 DOM 回读差两个数量级。** 位图路线的天花板是 DePlot 的 RMS_F1 94.2（合成图），
   分布外掉到约 78%。做 RLVR 只能走 DOM / 运行时路线。
7. **本机实测过程里 verifier 自己出了三个 bug，全是坐标系和帧的问题，不是阈值问题。**
   三个 bug 都会制造假阳性。详见 4.4——这是本文最该被记住的一节。

## 1 可逐值检查的清单

「怎么读」一列里，**几何**指从绘制坐标反推，**文本钩子**指拦截 canvas 文字绘制，
**DOM** 指直接解析 SVG 节点，**内部模型**指图表库自己的对象。

### 1.1 数据保真（这一族是本课题的核心）

| 查什么 | 怎么从产物里读出来 | 判据 | 误判风险 |
|---|---|---|---|
| 柱高与数值成比例 | 几何：由两个 y 刻度的像素位置拟合 `value = a·px + b`，再取柱子的 top 与 base 两个像素反推 | 每个 (系列, 类别) 的相对误差 ≤ 1% | 坐标轴是对数 / 断轴时线性拟合失效，要先读轴 type；堆叠柱的 base 不是零线 |
| 折线拐点与数据一致 | 几何：点元素的 (x, y) 逐个反推；没有点元素时解析 path 的 `d` | 同上，按类别对齐 | 平滑曲线（tension > 0）的控制点不是数据点，只能取锚点；抽稀后点数会少于数据点数 |
| 饼图 / 环图角度与占比一致 | 内部模型读 `startAngle / endAngle`；或解析 path 的弧命令反算圆心角 | 每个扇区占比与数据占比误差 ≤ 1% | 有间隙（padAngle）时角度和不等于 360 度，要先扣掉间隙总量 |
| 散点位置与数据一致 | 几何：点的 (x, y) 经两个轴分别反推 | 逐点双轴误差 ≤ 1% | 重叠点被合并绘制；抖动（jitter）是合法的，要在题面里说清 |
| 坐标轴范围 | 内部模型 `scale.min / max`；或由刻度文本的数值与位置反推 | 柱状图必须 min == 0；其余按题面 | 库会自动留白（nice 算法），所以 max 不应硬比，只能比「是否覆盖数据范围」 |
| 刻度与数据量级匹配 | 刻度文本 + 像素位置 | 刻度条数在 3 到 12 之间，且步长是 1/2/5 的 10 次幂倍 | 题面若指定刻度就以题面为准 |
| 数据标签与柱高自洽 | 文本钩子取绘图区内的数字文本，与同位置柱子的几何回读值比 | 两者相对误差 ≤ 1% | 这是**反作弊专用**：抓「柱子画错但标签写对」或反之 |

### 1.2 结构完整

| 查什么 | 怎么读 | 判据 | 误判风险 |
|---|---|---|---|
| 图例项数与系列数一致 | 内部模型 `legend.legendItems`；SVG 读图例分组 | 图例文本**有序**等于系列名有序列表 | 只比集合会漏掉「两个系列标签互换」，必须比顺序 |
| 轴标题与单位 | 内部模型 `scale.options.title`；文本钩子取绘图区外的长文本 | 非空且含单位记号 | 单位写在标题还是刻度后缀都合法，要两处都认 |
| 类别标签 | 刻度文本序列 | 等于输入类别序列 | 库会自动省略（autoSkip）密集标签，此时应比「可见标签是输入的子序列」 |
| 数据标签个数 | 文本钩子：文本盒中心落在绘图区内的文本 | 等于数据点总数 | 零值或负值标签可能被库跳过；重叠时库会自动隐藏 |
| 系列数 | 内部模型 datasets 中未隐藏的条数 | 等于输入系列数 | 辅助线、趋势线也是 dataset，要按 type 排除 |

### 1.3 可读性

| 查什么 | 怎么读 | 判据 | 误判风险 |
|---|---|---|---|
| 文字重叠 | 文本钩子 / DOM 拿每段文字的页面坐标包围盒，两两求交 | 任意两个文本盒的交集宽高都大于 1px 即判重叠 | **包围盒必须过变换矩阵**，否则旋转文本全堆在原点，假阳性成片（4.4 坑一） |
| 文字溢出 | 同上，与绘图区 / 画布边界比 | 文本盒越界即判 | 轴标题本来就在绘图区外，边界要分「画布」和「绘图区」两套 |
| 字号下限 | 文本钩子解析 `ctx.font`；SVG 读 computed `font-size` | 小于 9px 判挂 | 字号要乘以变换矩阵的缩放分量，否则缩放过的文字量错 |
| 对比度 | 文字颜色与其所在区域的背景色算对比度 | 正文不低于 4.5:1 | 文字压在柱子上时背景不是画布底色，要取文字盒下方的实际像素 |

### 1.4 图表类型与题面一致

| 查什么 | 怎么读 | 判据 | 误判风险 |
|---|---|---|---|
| 类型符合题面 | 内部模型 `config.type`；SVG 按图元构成推断（全是 rect 且共底 → 柱状） | 等于题面要求 | 混合图（柱 + 折线）有多个 type，要按系列分别认 |
| 朝向 | 柱子的宽高关系与基线方向 | 横向 / 纵向符合题面 | 题面没要求就不能查（见 5.2） |

### 1.5 SVG 特有

| 查什么 | 怎么读 | 判据 | 误判风险 |
|---|---|---|---|
| 路径可解析 | 正则切 `d` 为命令字母 + 数字流 | 首 token 必须是命令字母，且能完整切完 | 科学计数法、省略逗号、隐式重复命令都合法，正则要覆盖 |
| viewBox 合理 | 读 `viewBox` 与 `getBoundingClientRect` | 长宽比偏差 < 1%；缩放系数接近 1 | 刻意的响应式缩放是合法的，这一项只能当诊断，不能当硬闸 |
| 无光栅图冒充矢量 | 查 `<image>` 节点，以及 `fill` 里的 `url(#...)` 指向位图 | 存在位图即判挂 | 图标、logo 用位图可能是允许的，要看题面 |
| 元素数量合理 | 数 path 命令数与图元数 | 过少说明没画，过多说明在堆点 | 单条 path 画完整张图也合法，不能只数 path 个数 |

## 2 怎么读出来：四种产物的回读通道

### 2.1 四条通道对比

| 产物 | 通道 | 能拿到什么 | 是否公开 API | 被伪造的可能 |
|---|---|---|---|---|
| SVG（D3 / ECharts 的 SVG 渲染器 / 手写） | 直接解析 DOM | 图元的几何属性、文本内容与包围盒、`__data__` 绑定 | DOM 是标准；D3 的 `__data__` **不是公开 API**（官方入口是 `selection.datum()`） | 低。几何属性就是浏览器要画的东西，改了就真的变了 |
| canvas 图表库（Chart.js / ECharts canvas） | 库的实例注册表 + 元素像素几何 | 柱 / 点的像素坐标、坐标轴刻度像素位置、图例项 | Chart.js 的 `Chart.getChart` 与 `getDatasetMeta` 在官方 API 文档里；ECharts 的 `getInstanceByDom`、`getOption`、`convertToPixel` 是文档条目，但 **`getModel` 不是**，`getOption` 官方警告含合并后的默认值 | 中。模型可以挂一个假的实例对象 |
| 任意 canvas 产物 | **文本绘制钩子**（接管 `fillText` / `strokeText`） | 页面画出的每一段文字、位置、字号、颜色 | 标准 DOM API，与图表库完全无关 | 低。文字不经过这个函数就根本画不出来 |
| matplotlib | 读 figure 对象的 artist | `patches` 的 `get_height/get_xy/get_width`、`lines` 的 `get_xydata`、`get_xlim/get_ylim`、`get_xticklabels` | 全部是公开稳定的 Artist API | 低（进程内直读） |

### 2.2 为什么不要求模型暴露变量

和 `90_local_experiments.md` 的 three.js 结论一致：
要求模型写 `window.__CHART__ = chart`，训练时模型会学会「写这一行就行」，换 harness 就失效。

本文用的两条替代路径，都不需要页面配合：

- **库由环境提供**。harness 自己起本地服务，图表库从 `/lib/` 下发，页面不许访问外网。
  库文件在谁手里，实例注册表就在谁手里。
- **文本钩子在页面脚本之前注入**。`CanvasRenderingContext2D.prototype.fillText` 是所有 canvas
  文字的必经之路，拦住它就拿到全部文字，与用哪个图表库无关。
  本机实测参考解抓到 33 段文字：轴标题、图例、刻度、主标题、12 个数据标签，一段不漏。

### 2.3 伪造与反伪造

| 伪造手法 | 为什么能骗过 | 怎么防 |
|---|---|---|
| 把正确数据写进 `datasets[].data`，但用自定义绘制画错的柱子 | 配置回读看到的是对的 | 只认几何回读，不认配置回读 |
| 挂一个假的 `window.Chart` 实例注册表 | 库内部模型被污染 | 文本钩子与几何回读交叉验证；数据标签文本必须与柱子几何自洽 |
| 把数值用 `<text>` 写对，柱子画错 | 人看标签以为对 | 1.1 最后一行的自洽检查 |
| 离屏 canvas 画一张正确的图 | 回读读到正确的那张 | 只认挂在文档里、有尺寸、未隐藏的画布（沿用 three.js harness 的同一条规则） |
| 把 `viewBox` 缩小让内容整体放大 | 像素指标会一起缩放 | viewBox 与渲染尺寸的长宽比和缩放系数单独查 |

## 3 已有工作

### 3.1 逐值回读确实有人做过，而且是两条路

| 工作 | 回读方式 | 具体读什么 |
|---|---|---|
| **Chart2Code / From Charts to Code**（2510.17932） | 执行后 introspect matplotlib artist | 8 个维度里的 Data 维读 `xdata, ydata, offsets, xy, verts, width, height, sizes`；标量用 `numpy.isclose` 比，数组用 Jaccard；GT 元素贪心配同类型生成元素，算 P/R/F1。参考读数：Gemini-2.5-Pro 在 Level2 的 Data 分 0.756。容差 ε 的具体值论文未给（未核实） |
| **ChartMimic**（2406.09961） | code tracer 运行时拦截 | 同时执行 GT 代码与生成代码，拦截加文字的函数记 text，遍历 subplot 记 layout，记被调用的 plot 函数定 type，从返回实例读 color。四项各算 F1 再平均 |
| **Chart Specification**（2602.10880） | runtime interception of plotting objects | `S_code` 拿 values / nodes / edges / coords / positions / color，所以环图楔形占比这类隐含量也能还原 |
| **D3 Deconstructor**（Harper & Agrawala, UIST 2014） | DOM 的 `__data__` 绑定 | 从 DOM 抽出 data、marks 以及两者的 mapping（位置 / 宽高 / 颜色），有 Chrome 扩展。这是 DOM 层回读最早的原型 |

### 3.2 位图回读的精度上限，就是这条路当 verifier 的噪声地板

DePlot（2212.10505）把 chart-to-table 的指标定清楚了：

- **RNSS**：只比无序数字集合，不管表内位置，对很大的相对误差仍然给分。
- **RMS_F1**：每个 entry 是 (行头, 列头, 值) 三元组；键距离用归一化 Levenshtein，值距离用相对误差，
  超容差置 1；行列置换不变，转置不变靠取原表与转置表的较大值。τ 与 θ 的数值论文未给（未核实）。

PlotQA 全测试集 plot-to-table：

| 模型 | RNSS | RMS_F1 |
|---|---|---|
| ChartOCR | 81.0 | 60.1 |
| PaLI-17B (224) | 77.2 | 24.8 |
| PaLI-17B (588) | 90.5 | 74.9 |
| MatCha | 95.4 | 92.3 |
| DePlot | **97.1** | **94.2** |

数据解读：合成图上位图回读的天花板约 94.2，分布外（TaTa）掉到约 78%。
**即从位图回读自带 6% 到 22% 的误差，而从 DOM / 运行时回读原则上精确。**
PaLI-224 那一行还说明 RNSS 和 RMS_F1 的判别力差一个量级：RNSS 77.2 看着尚可，RMS_F1 只有 24.8。

### 3.3 数值抽取类评测的容差口径（可直接抄）

| 工作 | 口径 |
|---|---|
| ChartQA（2203.10244） | relaxed accuracy **继承自 PlotQA**（Methani et al. 2020），不是 ChartQA 自己定义的：数值相对误差 ≤ 0.05 判对，非数值要精确匹配；真值为 0 时退化成大小写无关的字符串匹配。原意是容忍「自动数据抽取」带来的误差 |
| ChartX / ChartVLM（2402.12185） | 结构抽取用 SCRM，先把 CSV 转三元组以获得行列与转置不变性，再按三档容差打分。普通图 e = 0 / 0.05 / 0.1；**困难图（玫瑰图、面积图、3D 柱、气泡、多轴、雷达）放到 e = 0.1 / 0.3 / 0.5** |
| CharXiv（2406.18521） | 2,323 张 arXiv 真图。GPT-4o reasoning 47.1%，InternVL-Chat-V1.5 29.2%，人类 80.5% |

数据解读：ChartX 对困难图把容差放到 0.1 至 0.5，等于承认这类图**从图上回读本身就不可靠**。
这正好反证：要零噪声就不能从图上读，必须从运行时读。
也因此，本项目的 1% 容差只在 DOM / 运行时路线上成立，不能套到位图路线。

### 3.4 像素相似度在图表任务上没有判别力：四组独立实测

| 来源 | 证据 |
|---|---|
| Plot2Code（2405.07990） | **MSE p = 0.22、SSIM p = 0.21，无法区分图组**，被明确弃用；CLIP-Score p 约 1.24e-4 能区分但没进最终三指标。最终三指标是 code pass rate / text-match ratio / GPT-4V 打分，与人类 920 组 pairwise 的 Kendall 0.437、Pearson 0.479、Spearman 0.469，作者自称「moderate」 |
| ChartMimic（2406.09961） | **CLIP Score 与人类判断相关性差被弃用**；执行态 low-level 与人类 Pearson **0.7681**，看图的 high-level（GPT-4o，不是 GPT-4V）只有 **0.7041**。作者把 low-level 更高归因于它依赖代码执行逻辑 |
| DePlot（2212.10505） | 与人类相关性：RNSS（只比数字集合）Pearson 0.46 / Spearman 0.84 → RMS_F1（带行列键的逐值比对）**Pearson 0.87 / Spearman 0.96** |
| ChartMaster（2508.17608） | 当 **reward** 用时：**pixel-level SSIM 把性能压到 SFT baseline 之下** |

四组证据方向完全一致：像素级几乎没有判别力，CLIP 居中，执行态逐值回读最高。
这和 `91_3jsbench_verified.md` 里 SigLIP2 在 3D 上的结论是同一回事。

### 3.5 SVG 方向：判据大多还停在像素，DOM 层是少数派

| 工作 | 判据 |
|---|---|
| StarVector（2312.11556） | SVG-Stack 约 2M，SVG-Bench 含 10 个数据集 3 个任务。图像向量化用 MSE / SSIM / LPIPS / DinoScore；Text-to-SVG 用 FID / FID-CLIP / CLIP Score。**唯一跑在代码上的指标是 Token Length**，其余全是光栅化后比图 |
| VGBench（2407.10972） | 覆盖 SVG / TikZ / Graphviz，4,279 理解 + 5,845 生成。理解按选择题准确率；**生成只有 CLIP score 加 FID，没有任何 code / DOM 层判定，连编译通过率都没有** |
| OmniSVG（2504.06263） | MMSVG-Bench 全是图像级指标，结构只体现在 tokenization 设计里，不在判据里 |
| SVGenius（2506.03139） | **有代码层**：parse XML 数 path 数、正则数数值参数、识别曲线命令算复杂度 |
| Reason-SVG（2505.24499） | 结构复杂度分数 = 数 path 命令与图元；有效性 = CairoSVG 能否渲染 |
| Leave-One-Out 结构指标（2604.08809） | 最接近 DOM 层判定：逐元素 render-with / without，导出 purity / coverage / compactness / locality。300 个 SVG 乘 3 个复杂度档、6 个系统、5 类编辑共超过 19,000 次。purity 与编辑精度 r ≥ +0.29（p < 0.001）；artifact 检测 LOO F1 ≥ 0.87，最佳 baseline ≤ 0.68 |

数据解读：SVG 是**所有产物里最该做 DOM 层判定的**（它本来就是文本结构），
但主流判据反而最依赖像素。这里有明显的空位。
Chat2SVG / LLM4SVG / RLRF Text2SVG 的具体判据未核实。

### 3.6 图表类 RLVR：可执行 reward 已经跑通

| 工作 | reward 设计与数字 |
|---|---|
| **Chart Specification**（2602.10880） | R = R_f + R_e + R_sem + R_code，GRPO 式组内优势。R_sem 先过**二元拓扑闸**（图表类型 + 面板布局 + 面板数），不过直接 0 并提前退出；过了再加 Coord、Domain（范围 IoU）、Series（Jaccard）、Data（编辑距离或 MSE）。ChartMimic 上 full 90.2 Pass / 78.4 Low，**去掉拓扑闸掉到 86.7 / 73.6**。没有做 pixel / CLIP reward 的对照 |
| **ChartMaster**（2508.17608） | R = R_attr + R_vis。R_attr 是属性集合 Jaccard，**数值差 ≤ 1% 算匹配**；R_vis 是 ResNet-18 四个 block 的特征图余弦均值。ChartMimic（Exec / Low / High）：baseline 65.5 / 39.9 / 34.2 → SFT 91.1 / 73.7 / 73.3 → ChartSimRL 93.8 / 78.2 / 77.3。消融：只 attr 92.1 / 76.2 / 75.2，只 vis 92.1 / 77.7 / 76.0 |
| Text2Chart31（2410.04064） | PPO，preference reward 加 code-描述 cycle consistency，**不是**逐值比对 |
| GeoSVG-RL（2605.25447） | SVG 图示，几何 / 布局约束 reward（元素并集是否在画布内、超出面积比例） |

两条可直接借鉴的设计：

- **拓扑闸提前退出**（Chart Specification）：图表类型错就直接 0，不给部分分。
  这与本文 S3 的「类型不符即判挂」是同一个思路，而且它有消融数字支撑（3.5 个百分点）。
- **1% 数值容差**（ChartMaster）：和本文跑之前独立写死的阈值撞上了，是个好旁证。

## 4 本机实测

机器：无 GPU，Chrome 148 无头 + SwiftShader，沿用 `06_harness.md` 的渲染栈。
代码 `scripts/vc_verifier/chart/`，复跑：

```
node build_cases.js && node run_all.js && python3 judge.py
python3 extras.py        # SVG 特有检查与可读性检查
./repeat.sh 5            # 噪声地板
```

### 4.1 任务与 harness

- 任务（`task.json`）：6 个城市两个季度的充电桩新增数量，分组柱状图，
  要求 y 轴从 0 开始并标单位、x 轴为城市、图例两项、每根柱子上方标数值。
- 参考解（`pages/ref.html`）：Chart.js 4.4.6，数据标签用自己写的插件以 `ctx.fillText` 绘制。
- harness（`harness.js`）做三件事，都不要求页面配合：
  - 在页面脚本之前接管 `fillText` / `strokeText`，记下每段文字的内容、页面坐标盒、字号、颜色；
  - 冻结时钟（`requestAnimationFrame`、`performance.now`、`Date.now`、`Math.random`），
    由 harness 调 `__vcStep` 推帧；
  - 图表库由本地服务下发，页面不许访问外网。

耗时（17 个页面，各起一次浏览器）：

| 阶段 | 耗时 |
|---|---|
| 单页全流程（启动浏览器 + 渲染 + 回读 + 截图） | 中位 840ms，最慢 939ms |
| 其中渲染（含推 240 帧） | 约 470ms |
| 其中**回读** | **1 到 4ms** |
| 其中截图 | 约 110ms |
| 17 个页面串行总计 | 14.5s |

数据解读：**回读几乎不要钱**，是渲染耗时的千分之四，比截图便宜两个数量级。
这一条直接决定了它适合放进 RL 的每一步，而截图不适合。

### 4.2 噪声地板

`./repeat.sh 5`：同一个参考页面重复渲染 5 次。

| 量 | 结果 |
|---|---|
| 几何回读（柱子 x / y / base，坐标轴刻度像素位置） | **5 次逐位完全相同** |
| 截图 md5 | **只有 1 种** |

数据解读：在冻结时钟 + 固定字体 + 固定 DPR 的条件下，这条链路没有随机性。
注意这比 `06_harness.md` 里 three.js 动画页的结论强——那里 20 次截图有 2 种，
因为那是「模型自由写的 rAF 动画」；图表库的终态是静态的，推够帧之后就稳定了。

参考解自比自：逐值回读最大相对误差 **0.15%**。
这 0.15% 不是随机噪声，是 Chart.js 的柱子 base 像素与零线差约 0.5px 的固定偏置，
每次完全一样。阈值 1% 对它有 6 倍余量。

  单点画错只让 0.75% 的像素变化，图例错位只让 0.01% 的像素变化。
  要抓住 0.01% 就得把阈值压到千分之一以下，那样换配色（30.51%）会被误杀得更狠。

### 4.4 实测中 verifier 自己出的三个 bug（本文最该记住的一节）

三个 bug 都会制造**假阳性**，也就是把正确的产物判挂。在 RL 里这是纯噪声。
三个都不是阈值问题，改阈值一个也修不掉。

| bug | 表现 | 真因 | 修法 |
|---|---|---|---|
| 文本跨帧累加 | 参考解「数据标签 360 个 != 12 个」，`animation` 变异被误杀 | 每帧重绘都会把所有文字重画一遍，钩子把 240 帧的记录全存下来了 | 给每条记录打帧号，只取**最后一个画了字的帧** |
| 动画没跑完就读 | `animation` 变异的 S1 误差 2.70%，超过 1% 阈值 | 只推了 30 帧（虚拟 480ms），而动画时长 800ms，读到的是中间态 | 推到 240 帧（虚拟 3.84s） |
| 文字盒没过变换矩阵 | 参考解报告 **171 对文字重叠**，实际 0 对 | 图表库普遍先 `translate` / `rotate` 再在局部坐标里 `fillText`，钩子记的是局部坐标，旋转文本全堆在原点。SVG 侧 `getBBox()` 同样返回未变换的局部坐标，旋转的 y 轴标题落到负坐标被判「溢出」 | canvas 侧把文字盒四角过一遍 `ctx.getTransform()`；SVG 侧改用 `getBoundingClientRect()` |

三条结论：

- **假阳性比假阴性难发现得多。** 前两个 bug 表现为「某个不该挂的变异挂了」，
  如果变异集里没有不该挂的一半，这两个 bug 会一直潜伏。
  **该挂 / 不该挂各半的变异集，第一价值是体检 verifier，不是评模型。**
- **坐标系是这类 verifier 的头号坑。** 三个 bug 里两个是坐标系。
  凡是「位置」参与判定的检查，都要问一句：这个坐标在哪个系里。
  SVG 的值回读还要再分一层：刻度位置必须用 SVG 自身坐标系（因为矩形的 height 属性也在自身坐标系），
  页面坐标只能给重叠和溢出用；混用会凭空多出一个 viewBox 缩放因子（实测把 25% 的误差读成 75%）。
- **修的是 harness，不是阈值。** `THRESHOLDS.md` 里的四个阈值从写下到最终结果一个没动。
  修 bug 之后 S1 从 12/16 变 13/16、S3 从 13/16 变 14/16，两个提升都来自消除假阳性。

### 4.5 SVG 特有检查与可读性检查

`python3 extras.py`，两个 SVG 页面（参考版 / 问题版）加一个标签拥挤的 canvas 页面。

| 检查 | svg_ref（参考） | svg_bad（问题版） |
|---|---|---|
| 逐值回读最大相对误差 | **0.02%** | **24.99%**（注入的是柱高乘 0.75，理论值 25%） |
| 回读样本 | 1280, 1640, 920, 1510, 760, 1050（与输入完全一致） | 960, 1230, 690, 1133, 570, 788 |
| viewBox 长宽比 | 合理 | 不合理，缩放系数 3.0 |
| 含光栅图 | 否 | **是** |
| 路径可解析 | 是 | 是 |
| 字号低于 9px | 0 条 | **6 条** |
| 文字重叠 | 0 对 | **9 对** |
| 文字溢出 | 0 | **5 条** |

数据解读：

- SVG 的逐值回读只用两个刻度文本的位置和矩形的 `height` 属性，**不读任何源码常量**，
  误差 0.02%，比 canvas 路线（0.15%）还低一个档，因为 SVG 没有 base 像素的 0.5px 偏置。

- 拥挤的 canvas 页面：字号检查抓到 6 个 7px 的数据标签，重叠检查在把刻度字号加到 22px 后抓到 2 对。
  canvas 和 SVG 两条路的可读性检查都跑通了。

### 4.6 口径与要打的折扣

- 变异集只有 1 个任务、16 个变异，**没有做留出验证**。
  `90_local_experiments.md` 的教训是前两个场景的结论要打折扣，本文同理：
  这 16 个变异上的 16/16 是「阈值没在它们身上调过」，但不是「换个任务也 16/16」。
  要补的是第二、第三个任务（折线、饼图），阈值一个不动再跑一次。
- 阈值只有 4 个，且都是在数据已知的前提下给的宽松值（1% 容差对应 0.15% 的实测偏置）。
  相比 three.js 那套（剪影 0.9、体素 0.9 / 0.5、分块 0.5、颜色距离 60），
  这里的阈值几乎没有调参空间，这本身就是这类任务的优势。
- S2 像素比对的两个阈值（通道差 8、占比 2%）确实只试过一组。
  但 4.3 的分析说明问题不在工作点选择：要抓的信号是 0.01%，要放过的噪声是 30%，中间没有空隙。
- 只测了 Chart.js 一个库。ECharts 的 `getOption` 官方警告含合并后的默认值，
  `getModel` 不是公开条目，所以 ECharts 的回读应当走 SVG 渲染器 + DOM，而不是内部模型。未实测。

## 5 结论

### 5.1 能不能做到零噪声 reward

**verifier 这一环可以做到零噪声，但「零噪声 reward」要看另外两环。**

| 环节 | 本机实测 / 依据 | 噪声 |
|---|---|---|
| 渲染可复现 | 5 次重复，几何回读逐位相同，截图 md5 单一 | **0** |
| 从产物回读数值 | 参考解 0.15%（canvas）、0.02%（SVG），且是固定偏置不是随机 | **0**（确定性偏置，不是噪声） |
| 数值与输入比对 | 1% 容差对 0.15% 偏置有 6 倍余量 | **0** |
| **题面到判据的对齐** | 未实测 | **这里才是唯一的噪声源** |

第四行就是 `90_local_experiments.md` 第 5 节那个坑在本课题的对应物：
verifier 能查的信息量必须小于等于题面给出的信息量。具体到图表：

- 题面没说「y 轴必须从 0 开始」，就不能查 `axis_min_500`；
- 题面没说配色，就不能查颜色；
- 题面没指定刻度步长，就只能查「步长是 1/2/5 的 10 次幂倍」这种弱条件，不能比具体值。

好消息是，图表任务的题面天然包含一张数据表，**数据保真那一族（1.1）永远是有授权的**。
所以可以这样切：

- **数据保真族 = 硬闸，零噪声**，任何图表任务都适用，不需要题面额外授权。
- **结构族、可读性族、类型族 = 按题面开关**，题面写了才查。
- 这个切法让 reward 的零噪声部分和有歧义部分彻底分开，不会互相污染。

对照学界：ChartX 对困难图把容差放到 0.1 至 0.5，是因为它从**位图**回读；
DePlot 的 94.2 是位图回读的天花板。走 DOM / 运行时路线就没有这个地板，这是本结论成立的前提。

### 5.2 在整个 visual coding 训练里的位置

**是性价比最高的入口，但不是能力上限最高的任务。**

性价比高在五点，每点都有本文或引文的数字支撑：

| 理由 | 证据 |
|---|---|
| 判定零噪声，不需要 VLM 投票 | 5 次重复逐位相同；而 `90_local_experiments.md` 里 VLM 单次判定最差两次一致只有 13/18 |
| 回读成本极低 | 1 到 4ms，是渲染的千分之四、截图的百分之一。可以放进每一步，不用算图像 token |
| 判据能指出挂在哪一项 | S1 给出「哪个 (系列, 类别) 差多少」，S3 给出「图例是什么、期望是什么」，可以直接当文本反馈喂回模型 |
| 任务可无限程序化生成 | 数据表随机生成，题面模板化，参考解不需要人写；这与 3D 任务要人搭场景完全不同 |
| 已有现成口径可对齐 | ChartMimic、Chart2Code、Chart Specification、ChartMaster 四套，不用自己发明 |

上限不高在三点：

- **产物的自由度低。** 一张柱状图的正确解空间很窄，模型学到的主要是「把库的 API 用对」，
  迁移到 three.js / Blender 这类需要空间推理的任务未必有帮助。
- **容易饱和。** ChartMaster 的数字：baseline 的 Low-level 39.9，SFT 之后就到 73.7，
  RL 再加 4.5 个点到 78.2。**SFT 吃掉了绝大部分涨幅，RL 的边际空间不大。**
  这说明图表任务更适合当「打通 RLVR 管线的第一块地」，不适合当长期的主力任务。
- **反作弊压力会转移。** 判定越严格，模型越会去钻题面没说的地方（配色、布局）。
  这一族的 hack 面比 3D 小，但不为零（见 2.3 的五种伪造手法）。

### 5.3 建议的落地顺序

1. **先做数据保真硬闸**（1.1 那七行），只对柱 / 折 / 饼 / 散点四种图，SVG 与 Chart.js 两条通道。
   这一步就能拿到零噪声的 0/1 reward，可以立刻接上 RLVR 管线。
2. **加拓扑闸并提前退出**：图表类型不符直接 0，不给部分分。
   Chart Specification 的消融说明这一步值 3.5 个百分点。
3. **结构族按题面开关**，题面模板里写了哪条就查哪条，保证 verifier 不比题面知道得多。
4. **可读性族只当诊断**，先不进硬闸。它的判据（重叠、溢出、字号）依赖坐标系，
   是 4.4 里 bug 最密集的地方，要先在变异集上证明零假阳性再提拔成闸。
5. **像素比对不要进 reward**。四组学界实测加本文的 9/16 已经足够。
   它唯一的用处是当「有没有画出东西」的执行门（画布全白 / 元素数为零）。
6. **补留出验证**：换两个新任务（折线、饼图），阈值一个不动，先写死标签再跑。
   这一步没做之前，4.3 的 16/16 要打折扣。
