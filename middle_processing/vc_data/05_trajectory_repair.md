## 0. 结论速览

**争议的答案是分层的，不是二选一。**

| 层 | 做法 | 最强证据 |
|---|---|---|
| **训练侧 · 错误步** | 错误前缀**留在上下文、不算 loss** | AgentRefine：错误轮算 loss 最差（Jericho Success 5.0，完整版也只有 5.0 但 Progress 26.2 对 18.4；SciWorld 原文称「接近 75% 下降」）；Agent-R、HSL 同路线 |
| **训练侧 · 负例 token** | 别删也别打 0，轻微降权或反向推开 | Verification Horizon：w_neg=0.0 得 37.2%、0.5 得 35.1%、1.0 基线 41.8%、**0.8 得 44.4%**；整条失败轨迹丢掉再 SFT 也无显著收益。Span-KTO（把负例当偏好反向推）SWE-bench Verified 54.2% → **59.8%** |
| **训练侧 · 死胡同分支** | **删**，但删完要重写衔接处的思考 | WebClipper：剪枝后 tool-call 轮数降 21%、token 降 19.4%，准确率不掉；去掉「上下文感知的选择性重写」后原文用词是 catastrophic collapse |
| **训练侧 · 绕路/无关动作** | mask loss | HSL：不 mask 无关来回动作时，真值数据最少的档位掉得最多 |
| **训练侧 · 纠错能力** | 离线修正轨迹做 SFT 学不到，必须 on-policy | SCoRe：STaR 的 Δ(t1,t2) 为 −14.2，加「对→对」数据后也只到 +0.4；SCoRe 本体 +4.4（MATH500），比 base 的 −11.2 高 15.6pp |
| **推理侧** | 删掉失败原文、**保留蒸馏后的教训** | AgentRewind：不回滚上下文 −21.9pp、去掉 rewind memory −36.6pp；RIR：只回滚 −7.38、只反思 −6.27 |

**三条反直觉的点，值得单独记住：**

1. **纯 clean 轨迹训出来的 agent 在干净 trace 上好，但不会恢复。**
   Agent-R 的修订能力测试：只用 optimal 轨迹训，平均 10.84；Agent-R 46.75；Direct-Revision 35.67。
   PALADIN 的 ToolBench-only 基线恢复率 32.76%，PALADIN 89.68%。
2. **「修复」必须扣掉采样随机性基线。**
   Real-Time Repair：「回滚 + 纯重采样」本身就有 16% 恢复率，带定位反馈才 45%。
   Repair or Resample：Self-Reflection 4.29、Critic 3.73，**都不如无指导全量重跑的 6.90**；
   温度 0 下重跑 54 条原本成功的执行，39 条至少退化过一次。
3. **失败轨迹不重写目标就直接喂，是负收益。**
   AgentHER 的 SFT-Random（同量失败数据直接 SFT）WebArena 14.7 / ToolBench 54.8，
   低于只用成功轨迹的 18.9 / 61.2。

## 1. 轨迹剪枝与压缩

### 1.1 WebClipper（arXiv 2602.12852，2026-02）—— 最接近「轨迹修复管线」的公开方法

- **建图**：LLM 抽取器（Qwen3-235B-A22B-Instruct-2507）把每轮「思考+动作」概括成一个**动作节点**，
  把每次观察拆成若干**原子信息节点**。边只有两种：信息→动作（这个动作依据了它）、动作→信息（它产出了这条信息）。
- **找最小必要 DAG**：动作节点代价 1、信息节点 0。Dijkstra 从 query 搜到 Answer 的最短路，
  再从 Answer 回溯补齐必要前驱。**不在子图里的动作全剪**。
- **投票**：建图+剪枝重复 3 次，至少 2 次得到完全相同的动作集合才采用。
- **重写思考（关键）**：剪完后，凡是原本不相邻、现在接在一起的两步，用 LLM 带完整上下文**重写后一步的 thought**；
  每次生成 3 个候选，取 base 模型自己算困惑度最低的那个。
- 数字（base = Tongyi-DeepResearch 30B-A3B，3 seed 平均）：

  | Benchmark | Base 准确率/轮数 | Eff 版 |
  |---|---|---|
  | xbench-deepsearch | 0.713 / 14.26 | 0.713 / 10.81 |
  | BrowseComp | 0.410 / 63.70 | 0.427 / 56.50 |
  | GAIA | 0.682 / 20.56 | 0.684 / 14.44（轮数降约 30%） |
  | HLE | 0.358 / 23.92 | 0.353 / 18.60 |

  总体 Eff 版 token 降 19.4%、轮数降 21%；Hybrid 版（混入无可剪的原始轨迹）准确率 +4.8%、轮数降 7%。
- **对照基线很说明问题**：让单个 LLM 直接删冗余轮（Coarse Prune）掉点严重（xbench 0.603、BrowseComp 0.220）；
  只加 prompt 控制则轮数几乎不降、准确率反降。
  → **「让模型自己看着删」是不行的，必须建依赖图。**
- 其他工程量：剪枝前按难度筛题（每题跑 4 次，只留通过率在 0 到 0.5 之间）；抽取+重写在 8 张 H800 上 1 天内跑完。

### 1.2 Step Entropy（arXiv 2508.03346，2025-08）—— 「哪些步是冗余」的量化判据

- 按每步的信息熵排序，剪掉低熵步。
- **核实过的数字**：剪掉**最多 80% 的低熵步**，最终答案准确率只有轻微退化
  （DeepSeek-R1-7B / 14B / Qwen3-8B），token 减少 16~45%；
  而剪**高熵**步会立刻掉点。
- 落地方式：SFT 教模型在该跳的地方输出 `[SKIP]` token，再用 GRPO 优化「准确率 + 压缩率 + 长度」的复合 reward。
- 注意：这是数学 CoT，不是 agent 轨迹。迁移时需要先验证「低熵 ≈ 冗余」在 agent 步级上是否成立（推断）。

### 1.3 推理侧压缩（判据可以直接搬到训练侧标注器）

**AgentDiet（arXiv 2509.23586，2025-09）**
- 人工检查 100 条 Trae Agent 轨迹，归纳出三类浪费：
  无用信息（`__pycache__` 列表、冗长的 make / pytest 输出）、
  冗余信息（str_replace 的参数和返回值重复）、
  过期信息（grep 后挨个打开但最终无关的文件）。
  → **这就是现成的「冗余步」分类法**，visual coding 版本见第 8 节。
- 机制：独立反思模块（GPT-5 mini），agent 走到第 s 步时只压缩第 s−a 步，
  上下文只给 s−a−b 到 s。**只改固定的较早步骤，所以之前的 KV cache 不失效。**
- 数字：被处理步骤里删掉 69.2~77.4% 内容；累计输入 token 降 39.9~59.7%；总成本降 21.1~35.9%。
  通过率不掉反升（SWE-bench Verified + Claude 64.5 → 66.5；Multi-SWE Flash + Claude 40.0 → 39.0 是唯一下降）。
- 超参（100 题 hill climbing 搜出）：θ=500（短于 500 token 的步不碰）、a=2、b=1。
  θ=0 时 62%，θ=2000 时 58%，θ=500 与原始持平 65%；a=0（压刚出来的那一步）掉到 59%。
  → **「只碰超过 500 token 且已经过去 2 步的长步骤」这条门控规则本身就是大部分收益**。
- **让 agent 自己删不行**：作者给过一个 erase 工具，Claude 4 Sonnet 和 Gemini 2.5 Pro 即使被强提示也几乎不调用。

**AttnCompress（arXiv 2609.08318，2026-09）**
- 用小代理模型（Qwen3-4B-Instruct）逐行算困惑度，在 PPL 差值的局部极大处切块（保住代码和 JSON 结构）；
  再用代理注意力给每块打分（最后一层、生成起始 token 对各块的平均注意力），贪心保留到预算满。
- 三层滚动窗口：最近 k=2 轮原样；中间短期区每轮重压；长期区冻结以命中前缀缓存；短期区满 M=10 轮触发全局刷新，被丢的块可以**复活**。
- 数字（SWE-bench Verified 200 题，3 个 agent 模型平均）：通过率 53.17%，原始不压缩 55.17%，
  AgentDiet 51.17%、SlidingWindow 49.83%、ObsMask 47.17%。
  输入 token 644.66k（原始 1118.16k，降 42.3%）；总成本 0.0949 美元/题（原始 0.1189）。
- 消融（100 题验证集，完整版 42.0%）：注意力打分换随机选块 35.0%；去掉滚动窗口 37.0%；PPL 分块换 token 级 39.0%。
- 动机数据（对管线有用）：**观察 token 占上下文 62.6%**；
  抽查 100 条摘要式压缩轨迹，**40 条出现「注意力回到早先内容」的焦点漂移**
  → 不可恢复的静态压缩会丢关键信息，这正是「不可能的思考」的另一面。
- 注意：摘要里的「token 降 21.6% / 成本降 33.6%」是**跟 AgentDiet 比**，不是跟不压缩比。

### 1.4 「replay final diff 反推最短路径」的现状

- **没有找到公开方法直接做这件事**（用最终 diff 反向生成最短轨迹）。最接近的是：
  - WebClipper 的最小必要 DAG（1.1）：形式上就是「从 Answer 反向回溯必要前驱」；
  - SWE-smith 的 PR Mirror（反转 PR 造 bug，2.2）：是在**任务侧**用最终 diff 反推，不是轨迹侧。
- **推断**：直接「看 final diff 重写一条干净轨迹」会掉进两个坑——
  ① 得到的是「teacher 一次写对」的分布，不是 policy 自己的分布（ReTerm 的分布不匹配论点）；
  ② 完全没有搜索/读代码的步骤，模型学不到定位能力（R2E-Gym 的 thought 消融侧面支持：剪掉 thought 后 SFT 从 34.2% 掉到 30.4%）。
  所以建议把「最终 diff」用在**校验**环节（第 9 节 ⑥），不要用它生成轨迹。

## 2. 拒绝采样与筛选

### 2.1 SWE-Gym（arXiv 2412.21139，2024-12）

- 2,438 个真实 Python 任务 / 11 个仓库，均带可执行环境和单测；SWE-Gym Lite 230 题。
- 拒绝采样微调：只用单测判通过的轨迹做 SFT。另训一个 ORM verifier（Qwen2.5-Coder-32B 读完整轨迹输出 YES/NO）。
- 数字：OpenHands + **491 条**轨迹 SFT（32B），SWE-bench Lite 3.0% → **15.3%**，Verified 7.0% → **20.6%**。
  Verifier 做推理时扩展（Verified）：Best@1 20.6、Best@8 29.8、Best@16 **32.0**（Pass@8 37.8、Pass@16 42.8）。
  LoRA 训的 verifier（29.8@8）优于全参（27.2@8）。
- **每题上限（per-instance capping）消融**（7B，SWE-bench Lite）—— 这是「按步数选最短成功轨迹」最直接的证据：

  | 每题最多保留 | 轨迹数 | 通过率 |
  |---|---|---|
  | 1 条 | 36 | 9.0% |
  | **2 条** | 62 | **9.7%** |
  | 3 条 | 82 | 7.7% |
  | 不设上限 | 172 | 9.3% |

  同一题内**优先留响应轮数少的轨迹**。491 条轨迹平均约 19 轮、约 19,000 token。
  → **「更多轨迹」不等于「更好」；每题 2 条、择短是经验最优点。**
- 反面教训：在线自我改进失败——868 条 on-policy + 491 条 off-policy，Lite 反而从 15.3 掉到 8.7。
- Verifier 训练数据：只留 32k token 以内的轨迹；成功/失败各 1,318 条共 2,636 条。
  只用 off-policy 数据时 Best@k 在约 22% 就停住。

### 2.2 SWE-smith（arXiv 2504.21798，2025-04）

- 环境优先：同仓库所有任务共用一个 Docker 镜像，再往里造 bug（LM 改写函数 / AST 变异 / 合并多 bug / 反转 PR）。
- 按执行结果筛：只留「至少打挂一个原本通过的测试」的候选；测试跑超过 2 分钟直接丢。
- 规模：5 万任务 / 128 仓库（平均 381 个/仓库），总成本约 1360 美元。
- 轨迹池：8,686 个任务做了 17,906 次尝试，成功 6,457 条（**36%**），每任务最多留 3 条，最终 **5,016 条**。
  平均 58 turn、约 29 个动作；生成上限 75 步、每条 2 美元。
- 结果：SWE-agent-LM-32B 在 Verified 40.2%、Lite 30.7%（SWE-Gym-32B 20.6%、R2E-Gym-32B 34.4%）。
  同样 500 条轨迹时 Verified 28.2%。
- **两条对筛选最有用的结论**：
  - **难度不决定训练价值**：按难度分 2/4/6/8 四档各 500 条，训后 Verified 为 12.4% / 10.8% / 13.6% / 12.2%（无单调性）。
  - **重复动作是主要的垃圾形态**：超过 25% 的轨迹出现长度 ≥10 的重复动作序列
    （Claude 3.7 低于 4%）；**长度 10 的重复对应 89% 的失败概率**。
    在 scaffold 上加干预能压住重复，但解决率不涨。
    → 「重复循环检测」是高价值、低成本的剪枝判据；但要注意它只是**失败的标志**，压住它本身不提升能力。

### 2.3 R2E-Gym（arXiv 2504.07164，2025-04）

- 从 commit 直接造任务（SweGen），没有现成测试就自动生成 F2P 测试；回译 issue 时把测试和执行信息喂进去。
- 两类 verifier：**执行型 EB**（训一个测试 agent，每次生成 10 个测试，先用回归测试过滤）、
  **非执行型 EF**（Qwen2.5-Coder-14B 读完整轨迹输出 YES 概率）。
  **混合 verifier**：先留 EF 前 n 名 → 回归过滤 → 按 EB 测试通过数 + EF 分数排序，EF 负责打破平局。
- 数字：8.1K 任务（去污染后 4578 题 / 10 仓库，附录写 4538，**原文前后不一致**）；
  3321 条轨迹训 32B，Verified Pass@1 **34.4%**。
  单一 verifier 的天花板：EB 停在 43.7%、EF 停在 42.8%（Best@26）；
  **混合 verifier Best@16 49.4%、Best@26 51.0%**（Pass@26 为 64.4%）。
- **EF verifier 消融（对剪枝的直接警告）**：

  | 输入 | 判别准确率 | Best@26 |
  |---|---|---|
  | 补丁 + 完整轨迹 | 71.82 | 42.8 |
  | 只给补丁 | 68.01 | 37.6 |
  | **轨迹去掉 thoughts** | 68.77 | 41.4 |

  EF verifier 很依赖 agent 自述的「我修好了」这类措辞 → **这类 verifier 容易被话术骗**。
- **训练时保留 thoughts：34.2% 对 30.4%** → 剪枝可以剪观察和动作，**不要剪思考**。
- EB 测试的局限：多数题里能区分对错补丁的测试不到 20%；有毒测试（通过错补丁、挂掉对补丁）最高占 10%。
- 合成 issue 与真实 issue 等价：各 400 条时 27.8% 对 28.0%。

### 2.4 SWE-Master（arXiv 2602.03411，2026-02）—— 两阶段过滤的工业口径

- teacher（MiniMax-M2 / GLM-4.6）在 SWE-Gym、SWE-rebench、R2E-Gym、SWE-smith 上每题 rollout N 次（3~12）。
- **格式过滤**：
  - 丢掉 reward 为 0 的轨迹；
  - 原文：剪掉**超过 80K token 或 100 turn** 的实例——这类只占已解决实例的 **5%**，但 OOM 风险不成比例地高；
  - 丢掉含无法解析的函数调用、或错误多次调用的轨迹。
- **难度过滤**：用 N 次 rollout 的平均解决率当难度，分布呈双峰，**去掉全对和全错的题**，只留有对有错的。
  - 不做难度过滤 54.2%（平均 94.57 轮 / 12,850 思考 token）；
  - 做难度过滤 **57.8%**（93.58 轮 / 12,678 token）。
- RL 后 61.4%（对照 daVinci-Dev-72B 58.5%、SWE-agent-LM-32B 40.2%）；
  TTS@8 用 SWE-World 模拟测试报告选候选，到 **70.8%**。
- **超预算强制提交**：轨迹因超时/超步数/超 token 被截断时强制提交补丁，reward 乘 α=0.5；容器故障的轨迹不计 loss。
  → 这是长程轨迹数据里必须有的一条工程规则（否则截断轨迹会变成噪声标签）。
- SFT 数据扩展：0 → 60K，解决率 6.2% → 57.8%，**48K 之后趋平**；
  同时平均轮数从约 115 降到 94、思考 token 从 14.8k 降到 12.7k
  → **数据量上去之后，模型自己会变短**。
- 注意：各数据集最终轨迹数表里相加约 1.26 万条，正文写「约 60K 实例」，**原文未解释这个矛盾**。
- 附带的摘要式上下文管理：M2.1 输入 token 降 42%、解决率 68.4 → 69.8；
  GLM-4.7 token 降 36% 但解决率 66.2 → 65.8；**用在它自己的 32B 模型上没有收益**。

### 2.5 用 verifier 做 best-of-N 筛 SFT 数据（前端场景唯一的公开数字）

Verification Horizon（arXiv 2606.26300，2026-06）§3.2：
用交互式 judge 做 best-of-4 拒绝采样微调（Qwen3.7-Plus 中间 ckpt）：
WebDev Human Eval 78 → **84**（+6），QwenWebBench 1509 → **1545**（+36）。

## 3. 纠错数据：怎么造、保留多少

### 3.1 Agent-R（arXiv 2501.11425，2025-01）—— MCTS 构造修订轨迹

- 同一棵 MCTS 树里，共享父节点的分支中 reward 低于 β=0.2 的是 bad、高于 α 的是 good。
- **由 actor 模型自己**在 bad 轨迹里找「第一个错误步」t′，在 t′ 截断、插入一句反思（10 条模板随机抽）、再接上 good 分支。
- **训练时 bad 前缀留在上下文但不计 loss**；loss 只算反思句和 good 后缀。
- 迭代 3 轮，α 依次 0.5 / 0.7 / 1.0；混入 ShareGPT 通用数据 η=0.2。
- 数字（Llama-3.1-8B，第 3 轮）：WebShop 63.91 / SciWorld 70.23 / TextCraft 78.00，平均 **70.71**；
  ETO 65.12、Direct-Revision 62.36、GPT-4o 45.46。
- **修订能力测试（最关键）**：把失败轨迹随机截断让模型接着跑——
  Agent-R **46.75**、Direct-Revision 35.67、只用 optimal 轨迹 **10.84**、GPT-4o 的 optimal 轨迹 8.34、ETO 13.08。
  只训干净轨迹的模型在 SciWorld 和 TextCraft 上几乎是 0。
- 另两条结论：
  - **「早截断」优于「末尾才修」**（46.75 对 35.67）；
  - 只训 optimal 更容易陷入死循环，revision 轨迹能显著减少重复动作序列（数值仅在图中）。
  - 往 optimal 里只掺 good（不掺 revision）**反而掉点**。

### 3.2 AgentRefine（arXiv 2501.01702，2025-01）—— 争议的核心消融就在这里

- GPT-4o 按 persona 合成剧本（环境 / 任务 / 动作 / 校验正则），再扮 DM + 玩家生成多轮轨迹，
  **要求至少包含 2 次「出错→修正」**，verifier 不过就重生成。默认 32,000 条。
- Refinement Tuning：**错误轮留在上下文、loss 置 0**，只学正确轮（含修正那一轮）。
- 消融（8,000 条数据，格式 Success / Progress）：

  | 变体 | Alfworld | BabyAI | SciWorld | PDDL | Jericho |
  |---|---|---|---|---|---|
  | 完整（错误 mask） | 48.5 / 61.5 | **37.1 / 51.7** | **7.7 / 33.1** | **21.7 / 37.4** | **5.0 / 26.2** |
  | 不对修正轮算 loss | 40.3 / 58.8 | 34.8 / 45.6 | 4.4 / 22.7 | 20.0 / 37.4 | 0.0 / 16.1 |
  | 干净数据（无错误与修正） | **49.3 / 65.2** | 30.4 / 43.1 | 5.5 / 21.3 | 11.7 / 32.5 | 0.0 / 13.8 |
  | 错误轮也算 loss | 29.9 / 43.9 | 23.2 / 31.6 | 3.3 / 19.0 | 8.3 / 28.3 | 5.0 / 18.4 |

  **两条结论**：
  - 换成干净数据后 **held-out 任务全面下降**，但 held-in 的 Alfworld 反而略高（49.3 对 48.5）
    → **「删掉试错」会换来域内小涨、域外大跌**。这是整场争议最干净的一组对照。
  - **错误步必须 mask**：错误轮也算 loss 是最差的一档。作者明确说这与 Ye et al. 2024 的结论相反。
- 泛化证据：对环境做扰动后，AgentGym 的 Success 平均掉 25.6%、Agent-FLAN 掉 30.4%，**AgentRefine +3.7%**。
  加 Reflexion 后 Alfworld 90.3（AgentGym 86.5、Agent-FLAN 83.1）。
- 但扰动下的 held-in 平均：干净数据 48.78、完整版 48.48，基本持平——差距主要在 held-out。

### 3.3 SCoRe（arXiv 2409.12917，2024-09）—— 纠错能力只能 on-policy 学

- 两轮自我纠错的在线 RL。Stage I 只优化第二轮 reward，同时用强 KL 把第一轮钉在 base 附近（解耦两次尝试、防行为坍缩）；
  Stage II 联合优化，第二轮额外加 α·(r2 − r1)：奖励「错→对」、重罚「对→错」。
- MATH500（Gemini 1.5 Flash）：

  | 方法 | t1 | t2 | Δ(t1,t2) | 错→对 | 对→错 |
  |---|---|---|---|---|---|
  | Base | 52.6 | 41.4 | **−11.2** | 4.6 | 15.8 |
  | Self-Refine | 52.8 | 51.8 | −1.0 | 3.2 | 4.2 |
  | STaR D+ | 53.6 | 54.0 | +0.4 | 2.6 | 2.2 |
  | Pair-SFT | 52.4 | 54.2 | +1.8 | 5.4 | 3.6 |
  | **SCoRe** | 60.0 | 64.4 | **+4.4** | 5.8 | **1.4** |

  Δ 的改善 = 4.4 −(−11.2) = **15.6pp**。
  注意原文内部矛盾：正文说「修错率 14.5%、base 为 9.5%」，与表里的 5.8 / 4.6 对不上。
- HumanEval（Gemini 1.0 Pro，只在 MBPP 上训）：SCoRe Δ=+12.2，base +3.0，差 **9.2pp**
  （摘要写 9.1%、正文写「9%」，三处不一致）。
  另外摘要把 MATH / HumanEval 对应的模型写反了，正文是 MATH 用 1.5 Flash、代码用 1.0 Pro。
- **离线修正轨迹做 SFT 为什么不行**：
  ① 分布偏移——学会纠正的是 base 的错，不是自己的错；
  ② 行为坍缩——学成「第一轮答好、第二轮不改」（编辑距离分析显示第二轮常常一字不改）。
- 组件消融（MATH）：去掉多轮训练 Δ=−2.4；去掉 Stage I +2.2；去掉奖励整形 +2.6；Stage II 换成 STaR +2.2。
- 推理算力对比：每题 32 样本时纯并行采样 +7.4%，并行 + 一轮自我纠错 **+10.5%**。

### 3.4 CLEANER / SAAR（arXiv 2601.15141，2026-01）—— 「分级重写」直接解决不可能的思考

- 机制：在 RL rollout 里，失败的工具调用被正确动作**覆盖**，得到自净化轨迹。
  覆盖粒度**按「错误代码与修正代码的语义相似度」自适应**：
  - **高相似度 → 浅层替换**：错误是表层的（语法笔误），原推理视为正确，丢掉失败动作和错误观察，
    把修正后的动作**直接接到原推理上**。
  - **低相似度 → 深层替换**：策略层面分歧，原推理与修正方案不兼容。
    **整个失败回合（推理+动作+错误观察）全删**，改用纠错时产生的辅助推理当正式推理。
    原文理由：保留过时推理会在训练数据里引入**语义失谐（semantic dissonance）**。
    → 这就是「不可能的思考」问题的机制化解法。
- **刻意保留 30% 原样**：对 Qwen2.5-7B 用随机混合策略，70% 走 SAAR、30% 不动，
  理由是「平衡 error avoidance 与 error recovery」，不牺牲推理时自己 debug 的能力。
- 数字：相对标准基线平均 AIME 约 +6%、GPQA 约 +3%、LiveCodeBench 约 +5%；
  匹配 SOTA 而只用三分之一的 RL 步数。
- 「内化」验证：推理时关掉 SAAR 这层脚手架，AIME24 Pass@1 只掉 0.6%、Pass@16 掉 1.3%；
  AIME25 Pass@1 掉 2.5%、Pass@16 反而 +0.2%。
- 出偏好数据的工程细节：把「原始失败动作 vs 修正动作」配成 online-DPO 对，
  **只对 tool-invocation 段落算 loss、其他 token 全 mask**，DPO 梯度与 GRPO 信号每步合并统一更新。
- 它反对的路线：对单个工具执行给稠密 reward 容易 reward hacking；
  rstar2-agent 式的超采样过滤（从 2 倍候选里留高质量）成本过高，
  因为 rollout 占 RL 运行时间的 80% 以上。

### 3.5 ReTerm（arXiv 2610.18484，2026-10）—— 错误必须来自 policy 自己

- 三段式造数据：
  ① base 模型跑终端任务，**保留失败尝试的交互历史和环境状态**
   （在 VM 里跑，attempt 结束时**先暂停 VM 拍快照、再恢复跑 verifier**，避免 verifier 自身改动污染快照）；
  ② 恢复快照，用更强的 teacher（DeepSeek-V4-Pro）**从失败状态继续**，
   只告诉它「上一次失败了」，不给隐藏测试的细节；
  ③ 过滤：verifier 过不了的、格式错的、不合规的、低效的全删。得到 ReTerm-10K。
- 作者明确点名人工注错的问题：**手工错误与 agent 自身执行错误分布不匹配**（针对 TermiGen）。
- RL 阶段：原始任务组和恢复任务组**分别算 GRPO 优势再合并**；
  每次更新采 8 个原始任务组 + 2 个恢复任务组；
  用**恢复任务队列**（新任务插队首、超容量淘汰最老）解决「单个 batch 里失败 rollout 太少」。
- 数字：ReTerm-9B 在训练 harness（ReAct）上比 Qwen3.5-9B **+14.6pp**，
  换到 Terminus-2 / mini-SWE-agent / OpenHands 仍 **+6.7~12.4pp**。
  消融：Base < SFT < GRPO < ReTerm-GRPO（具体数值在表 4）。
- 训练动态：恢复任务组的初始提升幅度更大，原始任务 reward 同时稳定上升——两者可以联合优化。

### 3.6 hindsight 重写：救失败轨迹

**AgentHER（arXiv 2603.21357，2026-03）**
- 四段式：失败检测（6 类 / 可恢复性 / 严重度权重 w，w < 0.3 直接丢）
  → 结果抽取（只抽观测里有证据的事实）
  → LLM 重写 user prompt（最多 3 次，置信度 ≥ θ=0.5）
  → 第二个 judge 复核 → 打包（SFT loss 按 w 缩放；DPO 的 chosen 是「新目标+轨迹」、rejected 是「原目标+轨迹」）。
- **轨迹一步不删**，只改目标。
- 数字：对 SFT-Success 提升 **+7.1~11.7pp**（WebArena：GPT-4o 23.4→30.5、Qwen-7B 18.9→27.8；
  ToolBench：Qwen-7B 61.2→72.9）。
  重写精度 **97.7%**（127/130，不是 97.1%）；单 judge 94.1%；3 名标注员 κ=0.82。
- 消融（WebArena / Qwen-7B）：完整 27.8（标签噪声 2.3%）；不做置信过滤 23.7（噪声 14.8%）；
  随机配 prompt 21.8；只 SFT 不 DPO 25.4；不做失败检测全接收 25.3；SFT-Success 18.9。
- **方法学疑点（引用时要说）**：表里把 GPT-4o 当可微调模型但没交代怎么训；
  训练与测试来自同一批 812 个 WebArena 环境，作者自承有泄漏风险。

**HSL / Spinning Straw into Gold（arXiv 2607.04235，2026-07）**
- on-policy 收轨迹（每步 18 条，缓冲 100），Llama-3.3-70B 零样本识别**所有实际达成的目标**
  （包括成功轨迹中途顺带完成的子目标），按目标截片段当成功演示；再标注每个动作「是否与新目标相关」。
- 两项技巧：**无关动作 mask loss**；按难度与最优性重加权采样。与真值演示按 λ=0.3 混合。
- 数字（Llama-3.2-1B）：ALFWorld unseen SFT 78.36 → SFT+HSL **97.76**；
  DPO 82.84 → DPO+HSL 94.78；PlanCraft 70.00 → 75.12；WebShop 63.81 → 66.97。
  样本效率：DPO+HSL 用 800 条真值演示就到 92.5%，DPO 用 3200 条以上也只有 82.8%。
  重标注准确率 90%（人工抽 200 条）。
- 消融：**不 mask 无关的来回动作**（NoMask）在真值数据最少时掉得最多
  ——弱 agent 有大量来回动作，学进去等于模仿次优策略。
  只对失败轨迹重标终点目标（传统 HER）一直明显更差，且不随真值数据量增加而改善。

**ECHO（arXiv 2510.10304，2025-10）**：同思路但是**纯 prompting**、不训练。
XMiniGrid-Stateful 上平均 reward 比 ReAct 高 80%、比次优基线高 42%。
作者自己指出局限：合成的反事实轨迹**不一定在真实环境动力学下可执行**——
这正是第 9 节 ⑥「必须重放校验」的理由。

### 3.7 PALADIN（arXiv 2509.25238，ICLR 2026）—— 配比的唯一公开数据点

- 5 万+ 条带恢复标注的轨迹，来自**系统性失败注入**（超时、5xx、限流、malformed 输出、部分结果，
  位置/频率/级联可配）+ teacher（GPT-5）续写恢复段，
  每条按 ToolScan 的 7 类错误标注恢复策略（诊断 / 重规划 / 改参数 / 重试 / 换工具）。
  LoRA SFT；推理时从 55+ 条失败范例库里检索最相似的一条。
- **配比 80% failure-rich / 20% clean happy-path**。
  但**附录 K.3 没有表、没有任何指标**，只有定性描述：
  「只用注入失败而不带 teacher 的恢复续写来训练，多轮行为会退化——
  过拟合到『重试一次』的启发式、学不会换计划换工具、CSR 因缺少有监督的结束状态而下降」，
  原文只写「RR 和 TSR 相对完整恢复标注训练下降，ES 惩罚更大」，没给数。
- 最接近「纯 clean」的对照是 ToolBench-only 基线（Gemma-3-12B，PaladinEval）：

  | 指标 | ToolBench Agent（只用成功轨迹） | PALADIN |
  |---|---|---|
  | 恢复率 RR | 32.76% | 89.68% |
  | 任务成功率 TSR | 57.4% | 78.38% |
  | 防幻觉 CSR | 68.37% | 82.55% |
  | 效率 ES | 0.221 | 0.312 |

  但这个对比**混入了推理时检索的效果**，不是干净的数据配比消融
  （去掉推理时检索：Gemma-12B 的 RR 89.7 → 61.4、TSR 87.4 → 57.3）。
- 原文内部不一致：摘要把 32.76% → 89.68% 称为「+57% relative」（实际是 +56.9pp 绝对），
  以及 89.86% 与表里 89.68% 对不上。
- **注意**：PALADIN 的「错误」是注入的**工具故障**，不是 agent 自己做错的动作。
  对 visual coding 的意义：环境类失败可以注入，**认知类失败（选错实现路径）只能从自己的 rollout 捞**（推断）。

### 3.8 配比小结

| 来源 | 配比 |
|---|---|
| CLEANER | 70% 重写 / 30% 原样 |
| PALADIN | 80% recovery / 20% clean |
| Verification Horizon | 负例 span 权重 0.8（不是删） |
| ReTerm（RL） | 每次更新 8 个原始任务组 + 2 个恢复任务组 |

## 4. 在错误处分叉重采样（rewind & resample）

### 4.1 AgentDebug（arXiv 2509.25370，2025-09）—— 找「最早的关键错误」

- 三阶段：① 按 AgentErrorTaxonomy 对每步的 memory / reflection / planning / action 四个模块打错误标签；
  ② 逐步做**反事实替换**，找出「改了就不会失败」的最早关键错误步；
  ③ 从该步 re-rollout，带针对性反馈；还失败就细化反馈，最多 N=5 次。
- 定位（AgentErrorBench 200 条，GPT-4.1，三环境平均）：All-Correct **24.3%** 对最强基线 0.3%；
  Step 准确率 45.0% 对 28.0%（GAIA 上 58.0 对 30.0）。
- 下游修复（ALFWorld，首次 → AgentDebug）：GPT-4o-mini 21 → 55；Qwen3-8B 48 → 74；Qwen3-Next-80B 60 → 84。
- 检测器很吃模型能力：GPT-4.1 的 All-Correct 32.0，其他模型都只有 2.0。
- 原文内部矛盾：算法 1 的注释写 Stage 2「no rollout/counterfactuals」，与正文的反事实测试冲突。
- 没有「找关键步 vs 随机步」的对照，也没有保留/删除试错的消融。

### 4.2 Real-Time Detection and Repair（arXiv 2608.02464，2026-08）—— 必须扣掉随机性基线

- 检测只用步级遥测（输出 embedding、token 不确定性、动作元数据），
  单类 ESN 集成 + CUSUM 报警；另加三条确定性校验（用实际工具结果重算答案总数、必需调用覆盖、工具返回形状合法）。
- 修复：回滚到**最后一个取数步**，前缀由日志重建，之后每步重新调用模型。
- 数字（n=55 个真错 episode，各 3 次独立重复的均值）：

  | 修复档位 | 恢复率 | p 值 | 每次恢复的调用数 |
  |---|---|---|---|
  | 不处理 | 0% | — | — |
  | **回滚 + 纯重采样（对照）** | **16%** | 对照 | 14.7 |
  | **located**：只说哪条校验失败、不给数值 | **45%** | 0.0005 | 6.4 |
  | generic：要求重新检查 | 36% | 0.0347 | 5.8 |
  | specific：给出带数值的发现 | 36% | 0.0192 | 8.1 |
  | recompute：要求用计算器 | 28% | 0.17（不显著） | 7.2 |
  | adaptive | 21% | 0.61（不显著） | 10.6 |

  Bonferroni α=0.01 下**只有 located 显著**，作者自称 generic / specific 只算「提示性」。
- 净效果：120 个 episode 上任务成功率 52% → 73%，恢复 25 个，**没有破坏任何原本正确的运行**。
- 两条对管线最有用的发现：
  - 26/55 条 specific 提示里直接带了正确总数，**却不比只说「哪条校验失败」的 located 更好**
    → 恢复不是靠「被喂答案」，是靠「知道往哪看」。
  - 按失败类型：只有 goal_drift 能靠重试修好（4/5）；
    tool_cascade 和 looping 重试只会拿回同样的坏结果，**必须升级处理**。
- 开销：监控每步约 200 微秒。

### 4.3 AgentRewind（arXiv 2608.14380，2026-08）—— 上下文和环境要一起回滚

- 每个决策点记对齐的 checkpoint：上下文 c_t + 工作区文件系统状态 s_t。
  rewind 是暴露给 agent 的**工具**：agent 自己选历史 checkpoint，并生成一段 **rewind memory**
  （总结被证伪的假设、可替代的策略）。
  执行时文件系统回滚、上下文恢复到 c_k 并**移除被丢弃分支的原文**、注入累计的 rewind memory。
  网络请求等外部副作用不回滚。
- 数字（MettleBench 82 题，GPT-5.4 + mini-SWE-agent，n=3，成功率 / 清单进度）：
  Continue 62.2 / 81.4；Restart with Experiences 78.0 / 88.8；Safety Review 34.1 / 54.4；**AgentRewind 87.8 / 94.3**。
  Terminal-Bench 2.0：Continue 78.7 / 88.7、AgentRewind 83.1 / 90.2。
  三种 harness 的提升：+25.6 / +23.2 / +15.8（成功率）。
  从同一失败状态出发的 50 对配对：Continue 恢复 8.0%、AgentRewind 30.0%。
- **消融（整场争议最直接的一组）**：

  | 变体 | 成功率 | 清单进度 |
  |---|---|---|
  | 完整版 | 87.8 | 94.3 |
  | 不回滚环境 | 43.9 | 63.5 |
  | **不回滚上下文（失败分支原文留在上下文）** | **65.9**（−21.9） | 77.9 |
  | **不留 rewind memory** | **51.2**（−36.6） | 69.4 |

  → **失败原文留着有害（−21.9），把教训压缩成 memory 保留有益（去掉 −36.6）。**
  这是「删观察、留推理骨架」在推理侧的精确对应。

### 4.4 Rollback-Induced Reflection（arXiv 2609.18304，2026-09）

- 把恢复拆成三问：
  - **何时回滚**：agent 主动请求 + 自适应定时审查，间隔 L 按紧急度在 [L_min, L_max] 间调整；
  - **回滚到哪**：**两阶段粗到细**——LLM 先圈出可能含决定性错误的历史区间，再在区间里挑
    「能摆脱失败条件的最晚 checkpoint」。原文理由：单遍扫全轨迹定位错误步不可靠。
  - **保留什么**：结构化反思记忆 =（任务目标，可复用环境知识，历次里程碑，最近一次失败分析）。
    **刻意不存当前状态**，以免回滚后把过期的状态说法带回来。
- 数字（平均成功率）：Qwen3-14B 47.00（Reflexion 43.91）；DeepSeek-V3 69.43（ReAct 62.86）；
  Qwen3.8-27B 76.54（Reflexion 73.50）。唯一输的格子是 Qwen3.8-27B 的 GAIA（50.66 对 52.63）。
  每题平均回滚次数 0.92~1.27，对照 GA-Rollback 约 2.9~3.1。
- 消融（ScienceWorld / DeepSeek-V3）：只反思不回滚状态 70.48；只回滚不带记忆 69.37；完整 **76.75**。
  → 两个半边都不够。

### 4.5 Repair or Resample?（arXiv 2608.25920，2026-08）—— 对整条路线的证伪性检验

- **SymTrace**：在模型/工具调用边界录制，组织成事件依赖图；回放时重启原生多 agent 系统，
  逐个请求严格匹配并注入录制结果，到锚点后才恢复实时执行。**前缀固定，下游变化才能归因到干预本身。**
- **SymFail**：200 个任务 × 3 个框架（AG2 / CrewAI / Magentic-One）= 600 条，留 536 条失败轨迹，
  人工标注失败节点和 C1~C4 类别（Fleiss κ：主类别 0.62、节点类型 0.81）。
- 复现同一失败（Rerun → Replay）：rep1 67.97% → **80.78%**；rep3 41.42% → 52.43%。
  复用前缀节点越多优势越大：复用 2~3 个 +9.80；4~8 个 +17.76;  9 个以上 **+25.69**。
- 修复（成功率，合计）：

  | 方法 | 尝试次数 | 合计 |
  |---|---|---|
  | Last-Node | 1 | 1.31 |
  | Random-Node | 1 | 3.73 |
  | Critic-Agent | 3 | 3.73 |
  | Self-Reflection | 3 | 4.29 |
  | **Unguided Full Rerun** | 3 | **6.90** |
  | **Suspicious-Node（规则+语义检测，按类别给修复指令）** | 1 | **20.15** |

- **三条必须记住的证伪结果**：
  1. **反馈类方法不如瞎重跑**：Self-Reflection 4.29、Critic 3.73，都低于无指导全量重跑 6.90。
  2. **重跑会双向翻转**：54 条原本成功的执行各重跑 3 次，162 次里 85 次失败；
     54 条里 **39 条至少退化过一次**——而且**温度是 0**。
  3. 案例：全量重跑「答对」的芝加哥降雪题靠的是常识猜出 30.00%，并没有拿到证据
     → 结果被判对，失败机制没被修好。
- 作者自承局限：「选哪个节点」和「给什么修复指令」是一起评估的，无法拆分贡献。

### 4.6 ReLook 的 Forced Optimization（arXiv 2510.11498，2025-10）—— visual coding 版的 rewind & resample

- 一次 refinement 只有在 reward **严格超过轨迹内历史最佳**时才被接受；不达标就重采，
  每轮最多 **10 次**重采；10 次都不行就终止该轨迹的反思、用历史最佳。得到**单调改进的轨迹**。
- **为什么不用罚分**：作者先试了「对退步给负 reward」，模型学会**减少反思次数**来躲罚（reward hacking），弃用。
- 消融（ArtifactsBench-Lite，3 seed）：21.59 → 24.89（+视觉 MLLM reward，+3.3）
  → 25.84（+不可渲染判零，+1.0）→ **27.88**（+Forced Optimization，+2.0）。
- 这个机制一举两得：**既生成纠错数据，又剪掉无效自检**。第 9 节的管线直接用它。

## 5. 过程监督与步级信用

这一节回答「怎么给每一步打分」。四类方案，可靠性递减、成本递增方向相反。

### 5.1 不训 PRM：靠轨迹结构算步级优势（首选，成本最低）

**GiGPO（arXiv 2505.10978，2025-05）**
- 两层相对优势相加：A = A_E（episode 级，同 GRPO）+ ω·A_S（step 级，ω=1 不调）。
- step 级分组靠**锚状态**：同一任务的 N 条轨迹里，**环境状态完全相同**的步用哈希表归成一组，
  组内用各步的折扣回报做相对优势。
  **不需要额外 rollout、不需要 critic、不需要奖励模型。**
- 数字（Qwen2.5，3 seed）：ALFWorld 1.5B 86.1（GRPO 72.8）、7B 90.8（GRPO 77.6、PPO 80.4）；
  WebShop 1.5B 67.4（GRPO 56.8）、7B 75.2（GRPO 66.1）。
- 开销：每轮迭代总 362.83 秒，其中分组 0.01 秒、优势计算 0.53 秒
  （原文写「小于 0.002%」，按这些数字算约 0.15%，**疑似把比例当成了百分数**）。
- 关键可行性数据：训练中只出现一次的状态（组大小 1）**始终少于 35%**，即超过 65% 的状态能参与分组。
  精确匹配不到时用相似度分组（最长公共子序列相似度 > 0.9 并组）。
  完全没有重复状态时 A_S=0，**自动退化成 GRPO**，下限有保证。
- **对 visual coding 的适配（推断）**：锚状态 = 工作区文件 hash + DOM 结构 hash + 场景图断言摘要。
  同一任务多条 rollout 在「刚起项目」「刚建好场景」这些点上大概率撞上同一状态。

**TreeRL（arXiv 2506.11902，2025-06）**
- EPTree 建树：先采 M 条链；在整棵树里挑**熵最高**的前 N 个 token 分叉，每个分叉点续写 T 条到结束，迭代 L 轮；
  靠近序列末尾的 token 屏蔽不让分叉。节点价值 V = 子树里答对叶子的比例。
- 步级 reward = [V(节点) − V(根)]（全局优势）+ [V(节点) − V(父)]（局部优势），
  再**除以子树叶子数的平方根**。完全 on-policy，不另训 PRM。
- 数字（Qwen2.5-14B，六基准平均）：TreeRL 44.5 对 ChainRL 41.6；AIME2024 28.0 对 22.2。
  采样 token 预算相当（TreeRL 每题 30 个回答，ChainRL 16 条）。
- 消融：去掉子树叶子数平方根重加权 → 平均 −1.9（非叶子步出现在多条序列里会被重复计梯度、过拟合）；
  只用全局优势 −1.3；只拿 16 个回答训 −3.2。
- PassRate（Omni-MATH-500）：熵分叉 56.9、随机分叉 54.8、多链独立采样 52.4。
  实际挑中的分叉点多是「wait」「But」「Since」这类转折词。
- **注意：TreeRL 的实验是数学和代码推理，不是 agent 环境。**

**SPA-RL（arXiv 2505.20732，2025-05）**
- 训一个进度估计器（LLM + MLP 头）对每个状态动作对输出贡献值，
  **约束是整条轨迹的贡献之和去拟合最终 outcome**（MSE），相当于把延迟 reward 重分配到每一步。
  每步 reward = α·进度贡献 + β·grounding（动作能否在环境里执行，0/1），α=1、β=0.5。PPO + GAE。
- 数字（Llama-3.2-3B）：ALFWorld unseen 79.1（StepAgent / RAGEN / ArCHer 均 75.4、PPO 73.9、SFT 73.1）；
  WebShop 64.1；VirtualHome 53.4。
  **25~29 步的长任务上比 PPO 相对提升 25%；0~4 步的短任务反而更差。**
- **最重要的对照**：把终局 reward 平均摊给每步（Mean）或用随机 reward（Random），
  效果不比纯 PPO 好、甚至更差。
  **只有满足「各步之和等于 outcome」约束的学习型分配才有用**，而且胜过 MC rollout 估计。
- 另一条：「动作能否执行」这类廉价 0/1 信号要**单独加进 reward**。
- 原文前后不一：正文说 ALFWorld grounding 准确率 91.7 / 比 StepAgent 高 3.6，
  但表 2 里 SPA 是 93.7、差值实际是 3.7。以表格为准。

**SWEET-RL（arXiv 2503.15478，2025-03）—— 和前端场景直接相关**
- 直接学 turn 级**优势函数**而非价值函数：同任务两条轨迹按累计回报分 chosen / rejected，
  用 Bradley-Terry 损失。A 的参数化 = response 每个 token 的 log(π/π_ref) **取平均（除以长度）**。
- **critic 能看到训练时才有的信息**（参考代码 / 参考网页），policy 看不到，是不对称 actor-critic。
  每个 turn 采 16 个候选，前 50% 当 chosen、后 50% 当 rejected，用 DPO 训 policy。
- 数字（ColBench，Llama-3.1-8B）：Backend 成功率 40.4（Multi-Turn DPO 34.4、拒绝采样微调 28.2、零样本 22.4；
  GPT-4o 也是 40.4）；Backend 测试通过率 56.8（GPT-4o 54.6）；
  Frontend 对 GPT-4o 胜率 48.2（Multi-Turn DPO 42.8）。
- 消融（Backend 成功率）：回归头 36.2；**不给 critic 训练时信息 31.2**；**不做长度归一化 3.6**。
  → 长度归一化不是细节：不除长度，actor 会学着越答越短直至塌掉。
- 数据少（3k 样本）时 SWEET-RL 不如 Multi-Turn DPO，数据多了才反超。

### 5.2 训 PRM：AgentPRM（arXiv 2502.10325，2025-02）

- PRM = turn 级 Q 函数。标签来自**异步 Monte Carlo**：同任务 rollout 多次，
  按状态动作对的哈希把经过它的轨迹聚成一组，组内平均折扣回报当 Q 估计，归一化到 0 到 1；soft BCE 训练。
  策略用 Online DPO 最大化 Q，**KL 约束到上一轮策略**（不是 SFT 初始策略）。三阶段迭代。
- 数字（ALFWorld OOD，最多 30 步，Llama3.2-3B）：64.9 → 73.9 → 85.8 → 88.1，BoN(N=16) 最高 91.0。
  对照 ReAct claude-3.5-sonnet 76.1、ReAct gpt-4o 65.7。
- **InversePRM**（只用专家示范、不用 outcome reward，靠 r = Q(s,a) − γQ(s',a') 恒等式学判别式 PRM）：
  86.6，对比同批专家数据上的 SFT 63.4、专家本身 91.0；**第 1 轮就到 82.8**，
  而用 70k rollouts 的 AgentPRM 才 73.9。
- **必须知道的失败模式**：PRM 用 10k rollouts 训时，400 步后成功率从 82% 掉到 70%，
  而**验证集上的 process reward 还在涨**——即 PRM 被打穿且在验证集上测不出来。作者试过 ensemble，没用。
  对策：KL 锚到上一轮策略、每轮用新 rollouts 重训 PRM。
- 探索技巧：Reset-50-50 峰值 82%、Steered Exploration 84%，基线 73.9%。

### 5.3 GUI / web 场景的 PRM（最接近 visual coding）

**Web-Shepherd（arXiv 2505.15277，2025-05）**
- 先把指令拆成**粗粒度子目标 checklist**（「过滤 A」「过滤 B」合并成「过滤」，以免对网站和动作顺序敏感）；
  打分时按 checklist 先生成反馈文本，再对每项判 Yes / In Progress / No。
  **每项分数 = P(Yes) + 0.5·P(In Progress)，用 verbalizer 从 logits 取概率**，多项取平均即该步 reward。
- 数据：WebPRM Collection，40K 步级偏好对，每个专家动作配最多 5 个被拒动作。
- 数字：WebRewardBench（WebArena 子集轨迹准确率）Web-Shepherd 8B 85.0、3B 65.0、GPT-4o-mini 5.0。
  WebArena-lite BoN 轨迹搜索（policy = GPT-4o-mini，每步 5 候选）：

  | PRM | 成功率 |
  |---|---|
  | 不做搜索 | 23.64 |
  | GPT-4o-mini（带 checklist） | 24.24 |
  | GPT-4o-mini（无 checklist） | 15.75 |
  | Web-Shepherd 3B | 32.12 |
  | **Web-Shepherd 8B** | **34.55** |

  policy 换 GPT-4o：基线 31.52 → 8B 39.39，而**用 GPT-4o-mini 当 PRM 反而降到 26.67**。
  WorkArena（完全域外）9.39 → 15.76。
- 成本（每 1000 实例，美元）：3B 为 **4.67**、GPT-4o-mini 43.57、GPT-4o 435.74、Qwen2.5-VL-72B 53.69
  （3B 口径：单张 A100 80GB、每小时 1.19 美元、按 vLLM 吞吐折算；每实例平均 81,287 输入 token、1,953 输出 token）。
- **三条可以直接抄的工程细节**：
  - **用概率打分，不要看采样出来的词**（3B，轨迹准确率）：
    单次温度 0 看输出词 12.2 → 单次取概率 43.1 → **5 次采样取概率平均 51.4**。
  - 训练时正负样本比 **1:4 优于 1:1**（WebArena-lite 32.12 对 24.85，8B）。
  - 用 BT loss 训练时 checklist 基本用不上、域外更差；多模态输入不一定涨分、有时还掉。

**Adaptive-Group Process Rewards（arXiv 2610.17710，2026-10）**
- 三段：
  - **分组**：critic 按指令和每步的 **response 文本（不看截图）** 把轨迹切成连续、不重叠的子目标组，
    不要求符合预设 milestone。
  - **动作级打分**：每组一次调用，给组内每个动作两个标签，查同一张表映射成 0 到 1 的分数（档位 0/0.2/…/1.0）：
    - 执行结果：Completed / Partial / Failed / Uncertain
    - **贡献**：Milestone / Useful-efficient / **Useful-inefficient** / **Exploratory** / **Redundant** / **Harmful**
      → 这套贡献标签几乎就是第 9 节步级标注要的分类法，可以直接借。判贡献时允许看组内后续动作。
  - **组级打分 + refinement critic 在看到全部组之后重审一遍**。
  - 每步 reward = 动作分 × 精修后的组分。
- 接入 GRPO：优势 = 组内 outcome 标准化优势 + α × process reward 标准化值（α=0.5），
  process reward 的标准化在同组所有轨迹的所有步上做。
- 数字：CUARewardBench 总体准确率 **81.3**（GPT-5 在 OpenCUA-Reflector 模板下 77.7、SE-WSM 模板下 74.9；
  同底座 Qwen3.6-27B 直接套模板 67.3 / 70.8）。CUAStepBench F1 39.9（SeekJudge-9B 38.1）。
  OSWorld 下游 RL（UI-TARS-1.5-7B，三次平均）：原模型 22.6、Outcome GRPO 30.4、SeekJudge 31.4、**本文 34.5**。
- 消融（CUARewardBench 总体准确率）：不分组 75.7；固定窗口（5 张截图）73.7；
  **分组时加截图 80.4**（比不加的 81.3 更差）；用和代替乘积 76.9；去掉 refinement 79.7；去掉 reference 77.9。
- **两条关键工程结论**：
  - **用乘积不用和**：改成和之后召回涨到 97.2 但特异度掉到 53.5（等于什么都判对）。
    「执行对」和「对任务有用」必须缺一不可。
  - **分组只看文本 response，别喂截图**：长得像的截图可能属于不同子目标，会干扰分组。

**VAGEN / Agentic Reward Modeling（arXiv 2602.00575，2026-02）**
- 定位要说清：**输出整条轨迹的成败 + 置信度，不给单步打分**。
- verifier 是带四个工具的 agent（Claude-Sonnet-4.5）：查看历史截图、shell、Python、computer use。
  **渐进式验证，先便宜后昂贵**：
  - Stage 1 静态判断：只看终态截图 + 操作摘要，不调工具；
  - Stage 2 **Visual Retrospection**：按操作摘要**自己挑历史步的截图**看，收集间接证据；
  - Stage 3 主动探查：用 shell / Python / GUI 查文件系统、配置等潜在状态。
  证据够了就停，结果取触发到的最深一级。
  另外先用 LLM 把 actor 的 reasoning 压成「观察 + 动作」，丢掉子目标分析，避免被 actor 的幻觉带偏。
- 数字（OSWorld-Verified，人工评测为 GT，Acc / F1）：
  Claude 当 actor：VAGEN 92.9 / 94.6、ProRe 87.3 / 90.4、ZeroGUI 83.7 / 87.7；
  UI-TARS 当 actor：VAGEN 93.4 / 89.3、ProRe 88.4 / 80.9。AndroidWorld 93.1（ProRe 91.4）。
  下游 GRPO（6K AgentSynth 任务，每任务 16 rollout）：UI-TARS 22.4% → **34.3%**，比 ProRe 高 3.8pp。
  BoN：N=5 就追平基线 N=8 的效果。
- **成本与消融（直接可抄）**：
  - 每条轨迹截图数 / 输出 token：VAGEN 11.9 / 1218，ProRe 24.2 / 1923。
  - 去掉翻历史截图的工具：准确率 83.1 → 80.5，**截图消耗反而从 11.9 涨到 18.4**。
  - 只保留翻截图、关掉环境交互工具：截图 5.4 张、准确率 78.5，接近全量 LLM-judge 水平但便宜得多。
  → **让 verifier 按需翻历史截图，而不是把整条轨迹塞给它。**
- 验证基本是只读操作，所以可以限制成只读、在同一个环境实例上串行跑 N 次投票，中间不用重置环境。

## 6. 上下文管理

### 6.1 Anthropic context editing（工程基线，非论文）

- `clear_tool_uses_20250919` 策略：上下文超阈值后**按时间顺序清最老的 tool result**，
  留占位文本告诉模型「这里被清掉了」；tool input 默认保留，可选 `clear_tool_inputs` 一起清。
  `clear_at_least` 保证每次清够量，否则不值得作废 prompt cache 前缀。
- 数字（Anthropic 官方博客 claude.com/blog/context-management）：
  100 轮 web search 评测里 token 消耗降 **84%**；
  单独 context editing **+29%**，memory tool + context editing **+39%**（内部 agentic search 评测）。
  博客未给 baseline 绝对分和评测集规模。

### 6.2 SelfCompact（arXiv 2606.23525，2026-06）

- 把 summarization 做成**模型自己调的 inline tool**，配一段轻量 rubric 告诉它何时该压。不微调。
  论点：固定 token 阈值触发的压缩「不管轨迹结构」，分不清模型是在推导中途还是刚解完一个子问题。
- 数字：比「不压缩」基线在数学上最多 **+18.1 分**、agentic search 上 **+5~9 分**，
  同时 per-question 成本低 **30~70%**；匹配或超过固定间隔压缩。
  消融：只给工具不给 rubric，七个开源模型的调用行为很不均匀；一段 rubric 就能补上。
- 可引用的机制描述（「死胡同必须剪」的最佳论证）：
  轨迹里积累的垃圾——早期的错误 case split、已经越过的搜索结果、走不通的候选程序——
  **不是静静躺着，而是锚定后面的一切**。
- 相关：ReSum（arXiv 2509.13313）主张用 summarization 而非改架构（内部 memory token），
  后者破坏与既有 agent 的兼容、需要昂贵端到端重训。

### 6.3 对训练侧的含义

- **冗余 tool result 在推理侧清掉就够了，不必在训练数据里剪。**
  训练侧剪枝要解决的是另一个问题：让模型**压根不产生那 30 步**。
- 但注意 SWE-Master 的反例：摘要式上下文管理用在 M2.1 上有收益（+1.4pp），
  用在它自己的 32B 模型上**没有收益** → 上下文管理的收益与模型自身的长程能力相关，不是免费的。

## 7. 关键争议：证据汇总

### 7.1 支持「保留试错」的证据

| 证据 | 数字 |
|---|---|
| AgentRefine：换成干净数据 | held-out 全面下降（BabyAI 37.1→30.4、PDDL 21.7→11.7、Jericho 5.0→0.0），但 held-in Alfworld 略升（48.5→49.3） |
| Agent-R：修订能力 | 只用 optimal 轨迹 10.84，Agent-R 46.75；只训 optimal 更易陷入死循环 |
| PALADIN：clean-only 基线 | 恢复率 32.76% 对 89.68% |
| Verification Horizon：删负例 token | 37.2% 对 44.4%（w_neg=0.8）；整条失败轨迹丢掉也无显著收益 |
| HSL：不 mask 无关动作 | 真值数据最少时掉得最多（弱 agent 的来回动作被当最优策略学进去） |
| AgentRewind：去掉 rewind memory | −36.6pp |

### 7.2 支持「删掉试错」的证据

| 证据 | 数字 |
|---|---|
| AgentRefine：错误轮也算 loss | 最差的一档（Alfworld 29.9，完整版 48.5）→ 保留 ≠ 学它 |
| AgentRewind：失败原文留在上下文 | −21.9pp |
| SelfCompact | 垃圾会锚定后续生成；压缩后数学 +18.1 分、成本低 30~70% |
| WebClipper：剪掉非必要动作 | 轮数降 21%、token 降 19.4%，准确率不掉 |
| Step Entropy | 剪 80% 低熵步仅轻微掉点，token 降 16~45% |
| SWE-Gym：每题择短 | 每题 2 条（择轮数少）9.7% > 不设上限 9.3% > 3 条 7.7% |
| SWE-smith | 超过 25% 的轨迹含长度 ≥10 的重复动作，长度 10 的重复对应 89% 失败率 |
| AgentHER：失败数据不重写就用 | 14.7 对只用成功轨迹的 18.9（负收益） |

### 7.3 调和

两边都对，因为它们删的不是同一个东西：

```
一个错误步 = 【推理：为什么这么做】+【动作】+【错误观察】
             ↑ 保留（骨架）           ↑ 删或改（CLEANER 分级）
             但不算 loss（AgentRefine / Agent-R / HSL）
```

- **删「观察和动作」**：有害的是它们——错误观察锚定后续生成（SelfCompact、AgentRewind、AttnCompress 的焦点漂移）。
- **留「推理骨架」且不算 loss**：有价值的是它——提供恢复能力和域外鲁棒性，
  但直接拟合它会学到绕路（AgentRefine 的「错误轮也算 loss」最差）。
- **深层错误连推理一起换**：策略级的错误，推理本身是错的，留着会造成语义失谐（CLEANER 低相似度分支）。
- **纠错能力本身只能 on-policy 学**：离线修正轨迹做 SFT 学不到（SCoRe）；
  错误必须来自自己的 policy（ReTerm 的分布不匹配论点）。
- **还没有人做过的事（本领域空白）**：纠错数据配比的系统扫描。
  现有四个数据点（70/30、80/20、w_neg=0.8、8:2 组比例）都是各自拍的。

### 7.4 一条容易被忽略的通路：不删也不留，改目标

AgentHER / HSL 走的是第三条路——轨迹一步不动，只把**目标**改成它实际完成的那个。
+7.1~11.7pp（AgentHER）、ALFWorld unseen 78.36 → 97.76（HSL）。
代价：会污染 prompt 分布；AgentHER 的训练与测试同环境，有泄漏风险。
建议单独成池、不超过总量的 10~15%（推断）。

## 8. visual coding 的特殊性

### 8.1 哪些自检有效

**① 报错 / traceback 驱动的重试：有效，但只修 API 错误**
- 3DCodeBench（arXiv 2606.01057，2026-06）：最多 2 次无状态的报错反馈重试，
  可执行率 **0.692 → 0.972**（表 1 汇总口径；正文写 0.702 → 0.974，**两处不一致**）。
- 但形状质量几乎不动：各家原生 coding-agent harness（墙钟 600~900 秒）把可执行率从 0.747 提到 0.973，
  在「两边都成功」的交集上条件 SigLIP 只变 **−0.010**、Chamfer +0.001、Uni3D −0.003。
- → **「能跑起来」和「做对了」是两件事，报错闸只管前者。**

**② 读确定性状态的检查：最有效的一类**
- SimWorlds（arXiv 2607.01766，2026-07）**刻意放弃图像 critique 循环**，直接查 Blender 活状态。
  四族规则：结构（集合层级、父子链）、几何（**BVH 测距**——声明接触的必须真接触、没声明却穿插的判失败）、
  软规则（落地、连通性、缺相机或灯光，只警告）、计划与状态比对（含运动时序，
  例如 settle 阶段最后几帧速度必须接近 0）。
  工具：`blender_scene_state` 读修改器栈 / 物理缓存 / 动画曲线；`motion_sheet` 按阶段边界逐帧采样。
  防作弊规则：求解器驱动的对象不许有密集关键帧，布料和软体不许用 shape key 驱动运动。
- 数字（4DBuildBench 50 场景）：

  | 指标 | SimWorlds | VIGA（纯视觉 verifier，Opus 4.7，15 轮） |
  |---|---|---|
  | 机制通过率 MPR | **0.87** | 0.67 |
  | 结构通过率 SPR | **0.89** | 0.70 |
  | VLM 评分 | 0.82 | 0.78 |

  **这组对比是全篇最有说服力的一个数据点**：MPR 差 0.20，而 VLM 评分只差 0.04
  —— 均匀抽 5 帧的 VLM judge 判断不了运动是怎么产生的，**手打关键帧的假物理也能拿高分**。
  流体类 MPR 0.95 对 0.56、刚体 0.83 对 0.61。
  消融（15 场景子集）：去掉 verifier → SPR 0.97 → 0.87（两个最难场景的 SPR 直接归零）；
  去掉分阶段 → VLM 评分 0.87 → 0.76。
- 3DHarnessBench（arXiv 2609.06535，2026-09）同向：读出确定性的量比多看图更稳定。
  GPT-5.6 Sol 加**相机位姿** SigLIP/Chamfer/Uni3D 从 0.9254 / 0.0199 / 0.7038 → 0.9419 / **0.0077** / 0.8387；
  Opus 5 加部件量测 Chamfer 0.0150 → 0.0099、Betti 拓扑误差 0.9050 → **0.4186**。
  注意「网格线 + 相机位姿」两个都加**不叠加**（0.9391 / 0.0110 / 0.8098），Betti 还最差。
- → **凡是能读引擎状态的检查，都不该交给截图去判。**

**③ 多视角 / 主动视角：对强模型有效，对弱模型有害**
- 3DHarnessBench 四档（Uni3D）：

  | 模型 | 单视角 | 多视角 | 主动视觉 | 完整 3D 交互 |
  |---|---|---|---|---|
  | Opus 5 | 0.725 | 0.748 | **0.871** | 0.927 |
  | Fable 5 | 0.733 | 0.764 | 0.832 | 0.884 |
  | GPT-5.6 Sol | 0.715 | 0.745 | 0.823 | 0.879 |
  | Kimi K3 | 0.678 | 0.713 | 0.819 | 0.848 |
  | Qwen 3.8 Max | 0.740 | 0.768 | 0.809 | 0.857 |
  | Gemini 3.1 Pro | 0.728 | 0.753 | **0.691（退步）** | 0.783 |
  | MiniMax M3 | 0.495 | 0.577 | **0.482（退步）** | 0.679 |

  多视角→主动视觉的变化：Opus +16.4%、Kimi +14.9%、GPT +10.5%、Fable +8.9%、Qwen +5.3%；
  **Gemini −8.2%、MiniMax −16.5%**。
  Chamfer 的最差/最好之比：固定视角约 2 倍，主动视觉 **8.5 倍** → 主动视角把模型差距放大。
- **退步的真因不是 3D 推理能力，是观察质量和探索纪律**：
  MiniMax 的主动视觉档 Uni3D 0.3722，**截图前先规范化视口**就回到 0.6148（多视角是 0.6200）；
  Gemini 0.6776 → 换用强模型采集的视图 0.7605（基本回到多视角 0.7609）。
  截图调用数：Gemini 8.00（过早停止）、**MiniMax 74.82（大量重复）**、Opus 26.15、GPT 25.73。
  MiniMax 在主动视觉档平均 431 次模型调用、156 次 MCP 调用、23.87 个重建版本。
  → **无效循环的两种形态：过早停止 和 重复看图。两者在同一档位同时出现。**
- 反面证据：3DCodeBench 把输入参考图从 1 张加到 4 张，条件 SigLIP-2 每个模型内**最多只变 0.012**，
  Gemini 3.5 Flash 在 N=2~3 达峰 0.60、N=4 回落到 0.56。
  → **给 verifier 多视角有效（3DHarnessBench 的档位是 agent 侧），给输入多视角收益不一致。**

**④ 截图用在「选择」而不是「生成」**
- BlenderAlchemy（arXiv 2404.17672，2024-04）文本驱动材质编辑（CLIP ViT-B/32 / ViT-L/14）：
  全部去掉视觉 25.7 / 21.8 → **只给 state evaluator 视觉 27.8 / 23.4** → 两边都给 28.2 / 24.0。
  → **截图在「打分和选择」环节值 +2.1 CLIP，在「生成改法」环节只多值 +0.4。**
- BlenderGym（arXiv 2504.01786，2025-04）的 verifier scaling：
  同一组候选打乱顺序跑 k 次淘汰赛再从 k 个胜者里选，k 越大三个指标全部变好；
  **scale 之后的 InternVL2-8B 超过不 scale 的 GPT-4o 和 Claude**。
- 算力分配（BlenderGym，VeriRatio = 验证占比）：总查询 < 30 时 VeriRatio 0.33 最好；
  总查询 > 100 时 0.73 最好。成本约每 100 次查询 0.45 美元。
  → **算力少时多生成候选，算力多时把预算给验证。**

**⑤ 交互前后的截图差**
- AesCoder（arXiv 2510.23272，2025-10）的交互美学 agent：先规划要交互的元素取 top-N，
  每做一个动作**对比动作前后的截图**判断页面是否正确响应，记 0 或 1，交互分 = 这些 0/1 之和。
  最终 reward = 0.1·执行 + 0.8·静态美学 + 0.1·交互。训练时交互元素最多 3 个（GUI agent 成功率低）。
- 消融（Qwen3-4B，InterAes 列）：SFT 0.62、RFT 0.71、DPO 0.70、
  **不用 agentic reward（只让 reward model 读代码文本打分）0.71**、完整 GRPO-AR **1.04**。
  → **只读代码的自评几乎等于没评。**
- 评测器可信度：与 Design Arena 排名 Spearman 0.98 / Kendall 0.91；GPT 与人一致率 80.9%，人与人 68.7%。
- 作者自承：交互 agent 失败时一律记 0，会系统性低估分数。

**⑥ 结构化、按阶段限定范围的 verifier 输出**
- Thinking in Blender / SEIG（arXiv 2606.02580，2026-06）：按艺术家工作流分阶段
  （初始化 → 几何 → 材质 → 构图 → 光照），**每阶段 verifier 只管本阶段因素**，其他阶段的错误一律忽略。
  verifier **不输出自由文本批评，而输出「审批清单」**（可执行 todo），注入下一轮 generator；满足清单才放行。
  每阶段轮数上限：几何 5、材质 3、构图 3、光照 2；到上限仍不过，由 verifier 挑最好的一次进下一阶段。
  材质阶段只允许调用「只能改材质」的工具，防止破坏前面阶段。
- 作者的核心论点：**自由文本批评在不同轮之间不一致，会给 generator 前后矛盾的目标，导致不收敛。**
- 数字（NeRF synthetic，generator 和 verifier 都是 Claude Opus 4.7）：
  SEIG 的 PSNR 13.58 / LPIPS 0.3493 / DreamSim 0.3021 / DINO 0.7188 / CLIP 0.8830，
  对 VIGA 纯 VLM 版 12.33 / 0.3506 / 0.3693 / 0.6221 / 0.8451；两个数据集 6 项指标赢 5 项。
  未给「去掉 verifier」的单独消融。

### 8.2 哪些是无效循环

| 形态 | 证据 |
|---|---|
| **不带回滚的串行自我修改** | BlenderAlchemy 去掉回滚，逐轮 27.1 / 26.4 / 26.6 / 25.8（**单调变差**），在改结构的 leap 轮掉得尤其明显；去掉视觉 27.4 / 26.1 / 26.5 / 25.7 |
| **过度串行或过度并行** | BlenderAlchemy 深度×宽度（共 32 次调用）：1×32 为 81.7 / 0.066 / 0.64，32×1 为 81.6 / 0.087 / 0.59，**两头都最差**；8×4 最好（84.1 / 0.050 / 0.50） |
| **只读代码文本的自评** | AesCoder 该档 InterAes 0.71，与 RFT / DPO 持平 |
| **单张或少量抽帧判动态正确性** | SimWorlds：MPR 0.87 对 0.67，而 VLM 评分只有 0.82 对 0.78 |
| **视觉自我批评在 image-to-3D 上** | 3DCodeBench 附录 D.2（最多 2 轮、给 4 张自己的渲染图）：text-to-3D 的 ΔSigLIP +0.003~+0.009（胜负比 1.24~2.63），**image-to-3D 的 ΔSigLIP −0.006~−0.009（胜负比 0.58~0.78）**；注意表里 Gemini 3.5 Flash 的 image 行是 +0.0126，**与正文「全部翻负」矛盾** |
| **弱 critic 过于激进** | 3DCodeBench：第一轮就判「不用改」的比例按能力排序——Gemma 4 31B 为 41%（49/119），较小模型只有 3%~13%；**回滚比例 31B 是 11%，较小模型 26%~28%** |
| **弱 agent 自主控制视角** | 3DHarnessBench：Uni3D 最多 −16.5% |
| **超过饱和轮次的继续打磨** | UI2Code^N（arXiv 2511.08195，2025-11）Table 3：UI2Code-Synthetic 92.0 / 97.0 / 97.0（**N=3 饱和**）；UI2Code-Real 66.0 / 68.0 / 70.0 / 73.0 / 74.0（**N=5 还在涨**）→ 饱和轮次是任务复杂度的函数，不是常数 |
| **行为坍塌** | ReLook：基座 Qwen2.5-7B-Instruct 在 2~3 轮后**即使拿到高质量反馈也越改越差**；ReLook 在 8 轮强制反思下保持单调改进。训练后反思频率收敛到约 2 轮 |

**一条重要的方法论警告**（3DCodeBench）：
不少「输」掉的修改其实视觉上更好——是**全局外观指标对几何改进不敏感**。
→ **用什么 reward 给每步打分，决定了同一个循环看起来有效还是无效。**

### 8.3 每一步怎么打分：截图 reward 差分的三个层级

| 层级 | 做法 | 来源 |
|---|---|---|
| **逐语句** | 缺陷区域与该语句渲染区域的 **IoU × 严重度** → 语句权重 w = 1 + (α−1)·resp，在 1 到 α 之间，语句内 token 共用，最后按权重之和归一化 | Visual-SDPO（arXiv 2606.10334，2026-06） |
| **逐阶段** | 只评本阶段因素，输出可执行审批清单 | SEIG / SimWorlds |
| **逐候选** | 打乱顺序多次两两比较取多数 | BlenderGym / BlenderAlchemy / UI2Code^N 的 RVPO |

**Visual-SDPO 的归因机制值得单独记**（这是「截图差分」最精细的落地）：
- 教师和学生是同一份权重，只是输入不同：学生只看 prompt，教师额外看到**学生自己代码渲染出来的结果**
  （图像通道，或一组二值缺陷表：对齐 / 遮挡 / 对比度 / 溢出）；代码执行失败时换成把 traceback 给教师。
- **教师不重新生成**，只在这份额外信息下对学生已写出的 token 重新打分，训练目标是逐 token KL。
- 从像素区域追溯到代码语句的两条实现路径：
  - **运行时插桩**：matplotlib 拦截对象构造函数记源码行号 + `get_window_extent()`；
    HTML 在 DOM 里加 `data-src-*` 属性配合 `getBoundingClientRect()`；pptx 拦截 shape 构造；
  - 没插桩的工具链退回用 VLM 做映射。
- 不画任何东西的语句（import、控制流）权重固定为 1，梯度集中在真正画出缺陷的语句上。
- 另加序列级 GRPO 项，reward = 执行 × 视觉，执行失败直接 0。推理时不需要渲染器和教师。
- 数字：ChartMimic Overall 零样本 67.9 → SFT 73.6 → GRPO（视觉相似度）76.2 → **Visual-SDPO 78.6**；
  Design2Code Overall 72.1 → 77.0 → GRPO 80.0 → **82.6**，提升最大的是空间类指标
  （Position 78.7 → 82.4、Block 64.5 → 69.7）；AeSlides 49.5 → GRPO 58.2 → **60.7**。
  **样本效率：达到 GRPO 训满的效果平均只用约 29% 的 rollout 预算。**
  未给 α、β 取值，也未给「去掉 credit weighting」的单独消融。

### 8.4 verifier 噪声地板（最容易踩的坑）

- **VLM 两两比较与人的一致率只有 0.66**（BlenderGym，7950 次判断、50 名参与者，
  最高的是 Claude 3.5 Sonnet），而**人与人一致率 0.79**，随机基线 0.5。
  Qwen 不管候选怎么排列总选第二个（位置偏置）。
- 人类基线：每任务最多 8 分钟，blend shape 的 PL 为 0.934，GPT-4o 为 9.140（差一个数量级）。
- Verification Horizon 的方差拆解（QwenWebBench 300 任务，各 5 次，ELO 标准差）：
  Claude Opus 4.7 生成 σ=10.4（range 24.4）、judge σ=8.5、Render+Judge σ=5.0；
  Qwen3.7-Max 中间 ckpt 生成 σ=2.8（极稳）但 **judge σ=11.4 成了瓶颈**。
  所有来源 σ < 12 ELO、最大 range 30.4，而模型档位间差约 40 ELO、Qwen Max 到 Qwen3-Coder-Next 差约 430 ELO。
- → **硬规则：用单次 VLM 打分的差分做剪枝判据，会把噪声当信号剪。**
  必须：① 重复 K 次（Web-Shepherd 的实测：单次看输出词 12.2 → 单次取概率 43.1 → **5 次取概率平均 51.4**）；
  ② 先量出自己的 σ；③ 只有差分超过 2σ 才允许判定。

### 8.5 前端 verifier 的三层（Verification Horizon §3，前端唯一的完整实测）

- **静态 rubric judge**（截图 + 源码）：671 个 WebDev 任务 × 8 个模型，
  每任务拆成平均 **25.9 条** checklist，六维占比 Functional 37.7% / Content 19.0% / Visual 13.3% /
  Layout 12.9% / UX 9.3% / Technical 7.2%。
  与人的一致性：Qwen3.6-Max 做 scorer 时 Spearman **0.905** / Kendall 0.786；Qwen3.7-Plus 0.810 / 0.714。
  同族内 Kendall τ=1.0，跨族 τ ≥ 0.93。prompt 严格度只改绝对分和分散度、不改排名；thinking level 影响可忽略。
  **明确的失效边界**：表单校验、动态路由、有状态交互没法读代码验；
  静态截图只是单一页面状态，覆盖不到多页跳转、过渡动画、下拉菜单 / 模态框 / 滚动触发内容。
- **交互式 agent judge**：三段式——action planner **一次性**生成完整动作列表（不逐步决策，避免复合误差）
  → Playwright 执行并录屏、记录每步状态变化 → judge 看采样帧 + 源码 + rubric 打分。
  动作词表预定义：click / scroll / navigate / fill form / hover / press key。
  预处理抽取 accessibility tree、browser state、keyboard listeners，并合成 Critical / Detail 两级 checklist。
  **做 RL reward 时：交互式 judge > hybrid > 纯视觉 judge**（test 分更高、输出长度稳定）。
  **把 checklist 喂给 action planner**：Claude 1517.3 → 1532.1、Qwen 1483.2 → 1498.6，方差不变。
- **长程项目级**：NL2Repo 104 个任务，evaluator 把 spec 拆成 checklist 打两个分
  （checklist 通过率、整体评分），用源仓库原测试套当近似 GT。
  rubric 版本 v1 → v4，BoN 准确率 57.9% → 67.4%、Kendall τ 0.379 → 0.473；
  **v5 过度细化（穷举禁止命令、加程序化护栏）反而全面变差** → rubric 不是越细越好。

## 9. 可落地的轨迹修复管线

输入：原始 150 步轨迹（含约 30 步试错），任务带 harness + verifier。
输出：SFT 数据（剪枝后的短轨迹 + 重写后的纠错片段）+ RL 数据（步级优势 / 偏好对）。

```
原始轨迹 ─① 快照化重放 ─② 步级打分 ─③ 步级标注 ─④ 剪枝/重写 ─⑤ 一致性闸 ─⑥ 重放校验 ─⑦ 出数
            环境可回滚      三路信号     六分类       分级替换      引用图闭包     必须复现终态
```

### ① 预处理：让轨迹可回滚、可重放

- **必须先把环境做成可快照的**，否则后面每步都没法独立验证。
  照 ReTerm 的做法：每次 attempt 跑在 VM 里的 task container，
  **attempt 结束时先暂停 VM 拍快照、再恢复跑 verifier**，避免 verifier 自身的改动污染快照。
- 快照内容：
  - 前端 / three.js：工作区 git tree + lockfile + 浏览器起始 URL + 已安装依赖层；
  - Blender：.blend 文件 + 脚本执行历史 + 资产引用清单。
- 记录每步完整 IO（reasoning、命令、观察）。照 AgentRewind 的口径：
  **上下文 checkpoint 和文件系统 checkpoint 必须对齐**，否则回滚一半等于没回滚（消融里不回滚环境 −43.9pp）。
- 产物：step_i → (前状态快照 id，推理，动作，观察，后状态快照 id)。
- 工具：docker commit / overlayfs / VM snapshot。

### ② 步级打分：给每一步一个带误差棒的分

三路并取，优先级从高到低：

1. **程序化检查（最可信，0/1 可判，不走模型）**
   - 前端：渲染是否成功、控制台是否报错、Playwright 动作是否全部执行成功、DOM 断言、关键 CSS 计算值；
   - three.js / Blender：场景图断言（对象数 / 层级 / 材质槽 / 修改器栈 / 物理缓存 / 动画曲线），
     **BVH 测距**验接触关系，运动时序断言（SimWorlds 的四族规则直接照搬）；
   - 便宜的 grounding 信号单独入 reward（SPA-RL：「动作能否执行」要单列，β=0.5）。
2. **交互式 judge**（Verification Horizon §3.2 三段式）
   - checklist 先合成（Critical / Detail 两级），**再把 checklist 喂给 action planner**（实测抬分且不增方差）；
   - 动作列表一次性生成、Playwright 顺序执行、录屏 + DOM diff + console；
   - judge 看采样帧 + 源码 + rubric 出分。rubric 做到六维约 26 条就够，**别过度细化**（v5 教训）。
3. **多视角视觉差分**（three.js / Blender 专用）
   - 固定 4~6 机位 + 1 个主动视角；**主动视角前先规范化视口**（MiniMax 0.3722 → 0.6148 的教训）；
   - 把相机位姿、包围盒、部件尺寸这些**确定性读数**一起给 verifier（比多给图更稳定）；
   - 比较方式用**相对排序**而非绝对分（UI2Code^N 的 RVPO；
     也别用 CLIP 全局相似度做 reward——UI2Code^N 实测会低于 SFT）。

**打分协议（硬规则）**：
- 渲染失败 / 脚本报错 → 直接 0 分，不进 VLM（ReLook 的零分硬闸，防 reward hacking）；
- 每步重复 K ≥ 3 次，**用 logits 概率而不是采样出的词**（Web-Shepherd：12.2 → 43.1 → 51.4）；
- 先在 50 条已标注轨迹上量出 σ_noise，写进配置；
- **verifier 按需翻历史截图，别把整条轨迹塞进去**（VAGEN：关掉翻截图工具，准确率 83.1 → 80.5，
  截图消耗反而 11.9 → 18.4）；
- 两个维度的分用**乘积不用和**（Adaptive-Group：改成和后召回 97.2 但特异度 53.5）。

### ③ 步级标注：六分类

每步算 Δ = reward(step_i) − best_so_far(< i)，结合程序化信号打标。
贡献标签直接借 Adaptive-Group 的六档：

| 标签 | 判据 | visual coding 的典型形态 |
|---|---|---|
| **Milestone** | Δ > 2σ 且程序化不退步 | 把布局/几何真改对了一块 |
| **Useful-efficient** | Δ > 2σ 但幅度小 | 调了个参数、确实变好 |
| **Useful-inefficient** | Δ > 2σ 但步数代价高 | 绕了三步才改对一个值 |
| **Exploratory** | \|Δ\| ≤ 2σ，但产生了后续被引用的新信息 | 换个视角看了一眼、读了文件 |
| **Redundant** | \|Δ\| ≤ 2σ 且后状态与前状态在断言级等价 | 反复截同一张首屏、重复 re-render |
| **Harmful** | Δ < −2σ，或程序化检查从通过变不通过 | 引入新 bug、改坏布局、脚本报错 |

**纠错段**另记一个 span 标签：紧跟 Harmful 之后、把 reward 拉回且超过出错前 best 的那一段。

**三个纯程序化的检测器（便宜且必要）**：
- **死胡同分支**：从 step_i 起的连续段，其后状态在断言级**全部被后续某步回滚**
  （文件 diff 被 revert、对象被删回去）→ 整段标死胡同。形式化用 WebClipper 的最小必要 DAG。
- **重复循环**：连续 ≥3 步的动作签名 + 观察签名近似重复。
  校准值来自 SWE-smith：**长度 ≥10 的重复动作序列对应 89% 的失败概率**，
  超过 25% 的轨迹含这种序列。
- **长度/预算越界**：照 SWE-Master 的口径剪掉超 80K token 或超 100 turn 的实例
  （只占已解决实例约 5%，但 OOM 风险不成比例）；
  因超预算被截断的轨迹**强制提交产物、reward 乘 0.5**，容器故障的轨迹不计 loss。

### ④ 剪枝 / 重写（顺序很重要）

先删死胡同，再处理错误步——否则会重写掉马上要删的东西。

1. **死胡同整段删**，不留摘要。它的后状态已被回滚，删掉不影响状态链。这是唯一能无损删的类别。
2. **Redundant 步删**，但要先过 ⑤ 的引用图闸。
3. **Exploratory 步保留**（它产生了被引用的信息），但可以压缩观察内容。
4. **Harmful 步做分级重写（CLEANER / SAAR 机制）**：
   算「错误动作」与「正确动作」的语义相似度（用 code embedding）：
   - **高相似度 → 浅层替换**：丢掉失败动作和错误观察，把修正后的动作**直接接到原推理上**。
     典型：参数写错、import 漏了、选择器写错。原推理是对的。
   - **低相似度 → 深层替换**：整个失败回合（推理 + 动作 + 错误观察）全删，
     改用纠错时产生的辅助推理当正式推理。
     典型：实现策略选错了（该用 shader 却去调材质参数）。保留旧推理会造成语义失谐。
5. **loss mask 策略（而不是删）**：
   - 被保留的错误前缀**不算 loss**（AgentRefine / Agent-R / HSL 一致路线）；
   - 绕路和来回动作**mask loss**（HSL）；
   - 整体负例 span 若要降权，取 **0.8**（Verification Horizon 的唯一超基线档）。
6. **纠错片段的配比**：起点 70% 重写 / 30% 原样（CLEANER），当超参扫。
7. **hindsight 重写（可选，救失败轨迹）**：AgentHER 四段式——
   失败分类（严重度 w < 0.3 直接丢）→ 结果抽取（只抽观测里有证据的事实）
   → LLM 改写 user prompt（置信度 ≥ 0.5）→ 第二个 judge 复核 → 打包（SFT loss 按 w 缩放）。
   visual coding 适配（推断）：让 VLM 看最终多视角渲染写出实际做成了什么，
   把目标改成「请做一个 <该描述> 的页面 / 场景」。
   **单独成池、不超过总量的 10~15%**（AgentHER 自承有环境泄漏风险，且会污染 prompt 分布）。

### ⑤ 防止「不可能的思考」（思考里引用了被删掉的观察）

这是剪枝最大的正确性风险。五道闸，建议全上：

1. **引用图（必须）**。为每步的 thought 抽取它引用的实体：文件路径、变量名、报错字符串、
   数值、选择器、「刚才那张截图里…」这类指代、对象/材质名。
   建 step → 被引用的上游 step 的有向图。
   **任何步被删，所有引用它的下游 thought 必须重写或同删。**
   实现：正则 + LLM 抽取双路，**实体落表，别靠 LLM 现场判断**。
2. **先验闭合，再删**。求传递闭包：要删 step_i，先看下游引用集；
   闸包里有 Milestone / Useful 步，则 step_i 不可直接删，只能走重写。
3. **衔接处必须重写 thought**（WebClipper 的实测：去掉这一步是 catastrophic collapse）。
   做法照它：原本不相邻、现在相邻的两步，带完整上下文重写后一步的 thought，
   生成 3 个候选，**取 base 模型自己算困惑度最低的那个**。
4. **SAAR 的相似度分级就是这道闸的机制化版本**（④.4 的低相似度分支一定要连推理一起换）。
5. **出数前的一致性审计**。用**独立的第三个模型**（不是生成的、也不是重写的那个）
   只回答一个问题：「有没有哪句话引用了上下文里不存在的信息？」
   命中就打回。**重复 3 次投票**，别单次（噪声地板见 8.4）。
6. 工程兜底：删 tool result 时留占位符而不是留空（Anthropic context editing 的做法）。
   **这是「保险但弱」的退化方案**，只在闸 1~5 判不准时用——代价是轨迹没真正变短。

### ⑥ 重放校验（硬门，不过就丢）

**剪枝后的轨迹必须在干净环境里重放，过三道校验**：

1. **可执行**：每步动作在新环境里都能执行成功（没有依赖被删步产生的中间文件）。
   注意 ECHO 自承的局限：合成/改写的轨迹**不一定在真实环境动力学下可执行**——这道闸就是为它设的。
2. **终态复现**：重放后状态与原轨迹终态**在断言级一致**。
   - 前端：DOM 结构 + 关键 CSS 计算值 + 截图感知哈希；
   - three.js / Blender：场景图断言 + 多视角渲染相似度。
   - **不要要求字节级一致**（随机种子、时间戳、浮点）。
3. **过 verifier**：重放产物过原任务 verifier，分数 ≥ 原轨迹终态分数 − ε，**ε 取 σ_noise 而不是 0**。

**可借用的回放工程**：SymTrace 的做法——在模型/工具调用边界录制、组织成事件依赖图，
回放时逐个请求严格匹配并注入录制结果，到锚点后才恢复实时执行。
它的数字说明回放本身有价值：复现同一失败 rep1 从 67.97% 提到 80.78%，
且**复用前缀节点越多优势越大**（9 个以上 +25.69）。

**要盯的指标**：
- 剪枝通过率。低于 60% 说明标注器太激进（推断）。
- 平均步数压缩比。参考值：WebClipper 轮数降 21%、token 降 19.4%；AgentDiet 输入 token 降 39.9~59.7%。
- **剪完之后 verifier 分布有没有漂**。若剪枝后平均分显著高于原始，大概率是选择偏差不是质量提升。
- **按步数分层看收益**：SPA-RL 的实测是步级信号在 25~29 步的长任务上相对提升 25%，
  在 0~4 步的短任务上**反而更差** → 短轨迹不要上这套管线。

### ⑦ 出数

**SFT**
- 剪枝后的短轨迹，thought 已重写并过一致性闸。
- 每题留 2 条、**同题内优先留轮数少的**（SWE-Gym：2 条 9.7% > 不设上限 9.3% > 3 条 7.7%）。
- 难度过滤：去掉全对和全错的题，只留有对有错的（SWE-Master：54.2% → 57.8%）。
- **不要剪 thought**（R2E-Gym：保留 thought 的 SFT 34.2% 对剪掉的 30.4%）。
- 纠错片段按 70/30 混入。
- 数据量参考：SWE-Master 在约 48K 条之后趋平；同时模型自己变短（115 轮 → 94 轮）。

**RL / 偏好数据**
- **首选不训 PRM 的步级优势**：GiGPO 的锚状态分组
  （visual coding 的锚 = 工作区 hash + DOM 结构 hash + 场景图断言摘要，推断）。
  它零额外成本、无重复状态时自动退化成 GRPO，下限有保证。
- 需要更细就用 SPA-RL 式的学习型分配，**必须带「各步之和 = outcome」的约束**
  （平均摊或随机分配都不比纯 PPO 好）。
- 做 critic 时：**优势函数而不是价值函数、对数概率比取均值且除以长度**
  （SWEET-RL：不做长度归一化只有 3.6%），并给 critic 训练时才有的特权信息
  （前端场景就是参考页面 / 参考代码；不给特权信息从 40.4 掉到 31.2）。
- 偏好对：SAAR 天然产出「失败动作 vs 修正动作」的同前缀配对。
  工程细节照 CLEANER：做成 online-DPO，**只对动作段算 loss、其他 token 全 mask**，
  DPO 梯度与 GRPO 信号每步合并统一更新。
- 负例别删也别打 0（见 7.1）。

**Forced Optimization 式数据构造（visual coding 强烈建议）**
- 重采被拒绝的步（上限 10 次），只保留严格改进的步 → 单调改进轨迹。
- **一举两得**：既生成纠错数据，又剪掉无效自检。ReLook 消融里它单独值 +2.0。
- **不要改成罚分**（模型会减少反思次数躲罚）。

### ⑧ 每步用什么工具 / 模型

| 环节 | 工具 | 模型 | 关键注意 |
|---|---|---|---|
| ① 快照 | docker commit / VM snapshot / git tree | — | 先暂停再拍快照；上下文与文件系统 checkpoint 对齐 |
| ② 程序化检查 | Playwright、headless Chrome、bpy、three.js 场景图 dump、BVH 测距 | — | 最高优先级，0/1 可判 |
| ② 交互式 judge | Playwright + 一次性 action planner | 最强档 VLM | checklist-guided；K≥3；取 logits 概率 |
| ② 多视角差分 | 4~6 固定机位 + 规范化视口的主动视角 | VLM 做相对比较 | 别用 CLIP 全局相似度；带上相机位姿等确定性读数 |
| ③ 标注 | 断言 diff + 规则 | 中小模型 | 死胡同 / 重复循环检测纯程序化；两维度分用乘积 |
| ③ 引用抽取 | 正则 + LLM 双路 | 中档模型批量 | 实体落表 |
| ④ 重写 | SAAR 分级；code embedding 算相似度 | teacher 级强模型做深层替换的辅助推理 | 浅层只换动作，深层连推理一起换 |
| ④ 衔接重写 | 困惑度选优（3 候选） | base 模型自己算 PPL | WebClipper 口径，不可省 |
| ⑤ 一致性审计 | — | **独立的第三个模型**，3 次投票 | 不能是生成或重写用的那个 |
| ⑥ 重放 | 干净容器 + 原 verifier；可选 SymTrace 式录制回放 | — | ε = σ_noise |

### ⑨ 不要做的事

- 不要只靠单次 LLM 打分决定剪谁（σ 可达判别效应量级；VLM 两两比较与人一致率只有 0.66）。
- 不要把错误整段丢掉就完事（37.2% 对 44.4%；AgentRefine 干净数据在 held-out 全面下降）。
- 不要让单个 LLM「看着删冗余轮」（WebClipper 的 Coarse Prune 掉到 0.220）。
- 不要指望 agent 自己调 erase 工具（AgentDiet：强提示下也几乎不调）。
- 不要对「改坏了」罚负分（模型会学会少反思）。
- 不要用人工注入的错误冒充 agent 自己的错误（ReTerm 明确点名分布不匹配）；
  环境类失败可以注入，认知类失败只能从自己的 rollout 捞。
- 不要在静态首屏上做自检闭环（静态 judge 做 RL reward 实测最差；只读代码的自评等于没评）。
- 不要给 generator 一个混合总分（SEIG：自由文本批评跨轮不一致会导致不收敛）。
- 不要剪 thought（R2E-Gym 34.2% 对 30.4%）。
- 不要忘了算随机性基线（纯重采样本身就有 16% 恢复率；反馈类方法可能还不如瞎重跑）。
- 不要把短轨迹塞进这套管线（SPA-RL：0~4 步任务上步级信号反而更差）。
- 不要信「验证集上的 process reward 还在涨」（AgentPRM：PRM 被打穿时验证集测不出来）。
