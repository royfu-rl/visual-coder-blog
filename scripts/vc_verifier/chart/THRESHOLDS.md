本文件在 `node build_cases.js && node run_all.js && python3 judge.py` 第一次执行**之前**写好。

## 任务

数据已知：2026 年 6 个城市两个季度的充电桩新增数量（台），见 `task.json`。
需求：画分组柱状图，y 轴从 0 开始，带 y 轴标题与单位、x 轴类别、图例两项、每根柱子上方数据标签。

## 三类信号，各自独立给判定

### S1 逐值回读（value readback）
从**绘制几何**反推数值，不读配置：
- 用坐标轴刻度的像素位置做线性拟合 `value = a * pixel + b`（至少两个刻度）。
- 柱子取 `top` 与 `base` 两个像素位置，回读出的值 = `fit(top) - fit(base)`。
- 判据：任一数据点相对误差 > **1%**（分母用该系列最大值，避免零值除爆）→ fail。
- 系列数或点数与输入不符 → fail。

### S2 像素比对（pixel compare）
候选截图与参考截图同尺寸逐像素比：
- 差异像素定义：RGB 任一通道差 > **8**。
- 判据：差异像素占比 > **2%** → fail。

### S3 结构断言（structural assertions）
- 图表类型 == 题面要求的类型
- 图例项数 == 系列数，且图例文本集合 == 系列名集合
- y 轴 min == 0（题面要求从 0 开始）
- x 轴类别标签序列 == 输入类别序列
- y 轴标题非空且含单位
- 数据标签个数 == 数据点总数
- 任一条不满足 → fail

## 口径

- 每个变异有人工先写死的标签 `should_fail`。
- 判对 = 信号给出的 fail/pass 与标签一致。
- 三类信号各自独立统计，不做组合（组合结果在报告里另算）。

## 补充口径（仍在首次运行之前写下）

- S1 的匹配方式：**按系列名匹配、按类别标签匹配**，即比较 `(系列名, 类别名) → 数值` 这张表。
  系列名或类别名对不上就算 fail（所以「图例与数据错位」「类别顺序错位」也由 S1 负责）。
- S3 的「数据标签」定义：文本钩子记录里，文本盒中心落在绘图区（chartArea）之内的那些文本。
  刻度标签在绘图区左侧或下方，标题与图例在上方，都不计入。
